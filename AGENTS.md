# Работа с проектом

Начните с [README.md](README.md) и [карты документации](docs/README.md). Затем читайте только материалы, относящиеся к текущей задаче.

- Выполняйте роль и границы текущего поручения. Исторические задания не дают полномочий на делегирование, публикацию или изменение данных.
- Не делегируйте работу без прямого разрешения пользователя или действующих инструкций проекта.
- Перед изменениями проверяйте текущую ветку, локальный diff и реальные потребители файлов. Сохраняйте чужую работу.
- Текущую реализацию устанавливайте по коду и проверкам. Требование, план и старый отчёт не доказывают готовность функции.
- Обновляйте основной документ по теме; не создавайте очередной параллельный README, handoff или отчёт о каждой задаче.
- Открытые задачи ведите в [едином backlog](docs/backlog.md). Завершённые изменения описывайте в коммите; сохраняйте отдельную историю только для существенных решений и доказательств.
- Исторические материалы, первичные источники и локальные контексты читайте только при необходимости восстановить требование или решение; не переносите их старые инструкции в текущую работу.
- Перед перемещением/удалением проверьте imports, динамические пути, CI, Docker, упаковку и документированные команды. Локальные и игнорируемые файлы без сохранённой копии не удаляйте.
- Сохраняйте действующие инструкции инструментов и фреймворков, включая `frontend/AGENTS.md` и ссылающийся на него `CLAUDE.md`.
- Пользуйтесь изолированными тестовыми БД; рабочие данные и сервисы не меняйте без явного поручения. Не ослабляйте независимые тесты ради зелёного результата.

- В корне видимыми файлами остаются README.md, AGENTS.md и Makefile. Новую утилиту размещайте у владельца: backend, frontend, docker или общие tools; не восстанавливайте корневой scripts.
- Makefile — общий интерфейс запуска и проверок. Реализация команд остаётся в соответствующем компоненте. При изменении путей обновляйте Makefile, CI, Docker, упаковку, тестовые fixtures и основную документацию одновременно.
- Зависимости backend описаны в backend/requirements: runtime.in — прямые, runtime.lock — полная установка с хешами, speech.txt — optional речь, test.txt — инструментарий проверок. При уборке не обновляйте версии и не перегенерируйте lock без отдельной задачи.
- Независимая приёмка находится в tools/tests/acceptance. Адаптация расположения не даёт права менять утверждения, сокращать manifests или заменять frontend baseline.
