# Структура проекта (112 Simulator V2)

Ниже описана актуальная структура директорий и их предназначение после переезда на новую архитектуру.

## Корень проекта (`/`)
- `README.md` — Главная документация проекта.
- `PROJECT_STRUCTURE.md` — Описание архитектуры и директорий.
- `run.sh` — Bash-скрипт для удобного запуска локального сервера (uvicorn).
- `seed.py` — Скрипт для заполнения БД тестовыми/стартовыми данными (пользователи, роли).
- `requirements.txt` — Список зависимостей Python.
- `.env` и `.env.example` — Конфигурация переменных окружения (включая настройки БД и ключи доступа).
- `pytest.ini` — Конфигурация для системы тестирования pytest.

## Директории
### `backend/`
Основной код серверной логики (приложения FastAPI).
- `main.py` — Точка входа, создание экземпляра FastAPI, регистрация CORS, роутеров и запуск миграций.
- `database.py` — Настройки асинхронного подключения к БД (engine, sessionmaker).
- `api/` — Роутеры и конечные точки (Endpoints).
  - Разделено по модулям: `router_auth.py`, `router_users.py`, `router_sessions.py`, `router_scenarios.py` и т.д.
- `core/` — Основная бизнес-логика и AI-инструменты:
  - `runtime_router.py` — Логика симуляции сессии (разговор заявителя и оператора 112).
  - `bricks_compiler.py`, `factoid_generator.py` — Модули для генерации и компиляции сценариев (на основе ИИ).
  - `tts_v2.py` — Синтез речи (Text-to-Speech) для имитации звонков.
  - `security.py` — Работа с JWT токенами и шифрованием.
- `models/` — Описание структур таблиц БД (SQLAlchemy Models). Разделены на домены:
  - `domain_01.py` — Пользователи, Группы студентов, Логирование действий.
  - `domain_02.py` — Тикеты сценариев (сохранение параметров генерации).
  - `domain_03.py` — Назначения, Экзаменационные сессии, Сессии по карточкам, Справочные материалы.
  - `domain_04.py` — Инциденты (карточки), Результаты оценки, Отчеты по сессиям.
  - `domain_05.py` — Фоновые задачи и расписания.
- `schemas/` — Pydantic-схемы для строгой валидации JSON-запросов и ответов API (Data Transfer Objects). Разделены по аналогии с API.

### `tests/`
Набор unit-тестов и интеграционных тестов для проверки всего функционала.
- Тесты на БД и модели (создание, ограничения, связи).
- Тесты на API (аутентификация, пользователи, CRUD сценариев и сессий).
- Проверки генерации SSE и взаимодействия с ИИ-ответами.

### `data/`
Локальное хранилище данных (например, здесь создается локальная SQLite база данных `112_simulator.db`).

### `docs/`
Дополнительная документация проекта (технические задания, спецификации и пр.).

### `prompts/`
Системные промпты и шаблоны для взаимодействия с языковыми моделями (LLM), которые управляют поведением заявителя и логикой сценариев.
