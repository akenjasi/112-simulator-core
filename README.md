# Тренажёр 112

Учебное приложение с FastAPI backend и React/Next.js интерфейсом. Основной сценарий ДДС: преподаватель готовит и утверждает билеты, назначает занятие, курсант последовательно обрабатывает карточки, преподаватель разбирает сохранённые действия и выставляет экспертную оценку. Самостоятельная тренировка курсанта доступна отдельно. Короткие сводки преподавателю и курсантам формируются после занятия в общей сохраняемой очереди на CPU с приоритетом учебной работы. Оценки считает код, Qwen3.5-4B даёт два предложения с рекомендацией. Явный фоновый режим также поддерживает суточные сводки за семь дней; нужен подготовленный локальный inference.

Ссылка на рабочий прототип: https://51.250.34.5

Код также содержит операторский тренажёр, ASR, интеграционные адаптеры и несколько поколений аналитики. Их наличие не означает готовность внешних сервисов. Речь и нейроотчёты требуют подготовленных моделей и сервисов; реальные SIP/SPO112 остаются отдельной интеграционной приёмкой.

## Начало работы

Нужны Linux, Python 3.11, Node 22 (не ниже 22.12), npm и GNU Make. Для контейнеров — Docker с Compose; сборка образов использует BuildKit. `make help` показывает команды; простое `make` тоже только выводит справку.

```bash
make install
make init
make models
make backend
```

В другом терминале: `make frontend`. Интерфейс — http://localhost:3000, API — http://localhost:8000/docs. Установка создаёт `.venv`, использует hash lock backend и npm lock; ASR не включается автоматически. `make models` готовит веса Qwen TTS, синтез включён в новом `.env`; приложение само ничего не скачивает. `make init` создаёт приватный `.env` с уникальными секретами и отказывается перезаписывать существующий.

БД локального backend находится в `data/112_simulator.db`; явный DATABASE_URL имеет приоритет. Уже существующая старая корневая SQLite поддерживается до её явного переноса. Начальный ADMIN создаётся при startup, пароль берётся из конфигурации.

При первом запуске с пустым каталогом автоматически устанавливаются четыре утверждённых
учебных билета ДДС: дерево, прорыв воды, лифт и запах газа. Набор поставляется с кодом
и Docker-образом, работает с SQLite и PostgreSQL. Существующий каталог и история
сохраняются; подробности — в [сценарии ДДС](docs/product/dds.md#четыре-городских-демобилета).

## Команды проекта

| Задача | Команда |
|---|---|
| Основные проверки | `make test` |
| Проверки плюс полный backend diagnostic | `make test-all` |
| Подготовить TTS / TTS и LLM | `make models` / `make models WITH_LLM=1` |
| Собрать два Docker-образа | `make build` |
| Подготовка моделей, Docker-сборка и запуск | `make up` |
| Запуск готовых production images | `make up-prod` |
| Логи / остановка с сохранением томов | `make logs` / `make down` |
| Backup локально настроенной БД | `make backup` |
| Параметры offline-упаковки | `make package-offline ARGS="--help"` |

Makefile работает также через `make -C /absolute/path/to/project …`. Для существующей Python 3.11 среды задайте VENV. Для Compose доступны ENV_FILE и PROJECT; реальный env-файл и секреты в Git не добавляются. Установка зависимостей и загрузки не выполняются обычным запуском приложения.

## Где что находится

- `backend` — сервер, его зависимости, служебные команды и тесты.
- `frontend` — интерфейс, npm-настройки и его тесты.
- `docker` — сборки образов, Compose, Nginx, контейнерные команды и автономная поставка.
- `tools` — подготовка конфигурации и общие проверки репозитория.
- `assets` — поставляемое аудио и справочники; `models` — модели и связанные ресурсы.
- `data` — рабочая БД, uploads, backups, локальные сертификаты, результаты проверок и пакеты. Не очищайте эту папку как сборочный мусор.
- `docs` — [карта документации](docs/README.md), [открытые задачи](docs/backlog.md), отдельно история и первичные источники.

Агент начинает с [AGENTS.md](AGENTS.md). Docker-настройка описана в [развёртывании](docs/operations/deployment.md), проверки — в [testing](docs/testing.md), перенос на сервер — в [offline](docs/operations/offline.md).
