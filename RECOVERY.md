# Инструкция по аварийному восстановлению базы данных (Disaster Recovery)

Данный документ описывает процедуру восстановления базы данных из резервной копии в случае критического сбоя оборудования или тотальной потери данных.

Наш скрипт `scripts/backup_db.py` автоматически создает резервные копии в папке `data/backups/`.
В зависимости от используемой БД, резервная копия будет иметь формат `.db` (для SQLite) или `.sql` (для PostgreSQL).

## Восстановление PostgreSQL (Docker)

Если ваша система развернута на PostgreSQL через Docker (как описано в `docker-compose.yml`), выполните следующие шаги для восстановления из дампа `.sql`:

1. **Убедитесь, что контейнер с базой данных запущен и база пуста:**
   Если вы разворачиваете систему с нуля на новом сервере, сначала запустите контейнер:
   ```bash
   docker compose up -d postgres
   ```
   *Дайте базе несколько секунд на инициализацию.*

2. **Скопируйте файл дампа в контейнер:**
   Найдите последний `database_YYYYMMDD_HHMMSS.sql` файл в вашей резервной папке и скопируйте его внутрь контейнера `simulator_postgres`:
   ```bash
   docker cp ./data/backups/database_20260927_120000.sql simulator_postgres:/tmp/recovery.sql
   ```

3. **Запустите команду восстановления (psql):**
   Выполните импорт дампа в базу данных `simulator112` от имени пользователя `admin` (убедитесь, что параметры совпадают с вашим `.env`):
   ```bash
   docker exec -it simulator_postgres psql -U admin -d simulator112 -f /tmp/recovery.sql
   ```

4. **Проверьте данные и перезапустите бэкенд:**
   ```bash
   docker compose restart backend
   ```

## Восстановление SQLite (Локально)

Если система работала в упрощенном режиме (на SQLite):

1. **Остановите бэкенд** (чтобы избежать блокировок файла):
   ```bash
   docker compose stop backend
   ```
   *(Или остановите локальный процесс Uvicorn)*

2. **Замените поврежденную БД на резервную копию:**
   Найдите ваш бекап (например, `112_simulator_20260927.db`) и скопируйте его на место активной базы:
   ```bash
   cp ./data/backups/112_simulator_20260927_120000.db ./data/112_simulator.db
   ```

3. **Запустите сервер:**
   ```bash
   docker compose start backend
   ```

---
*СОВЕТ ДЛЯ СИСАДМИНА: Настройте `cron` задачу на сервере для регулярного переноса содержимого `data/backups/` на внешнее хранилище (NAS или S3), чтобы обезопасить систему от физической гибели дисков.*
