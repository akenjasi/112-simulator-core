# 112 Simulator V2 — Docker Deployment Bundle

Автономный портативный пакет для сборки и запуска тренажера-симулятора службы 112 на любой операционной системе (Linux, macOS, Windows) с установленным Docker.

---

## ⚡ Быстрый старт (в 1 команду)

### Вариант 1: Использование Docker Compose (рекомендуется)

1. Перейдите в данную директорию:
   ```bash
   cd docker_standalone
   ```
2. Запустите контейнер:
   ```bash
   docker compose up -d --build
   ```
3. Откройте в браузере:
   - **Веб-интерфейс:** [http://localhost:3000](http://localhost:3000)
   - **API Swagger документация:** [http://localhost:8000/docs](http://localhost:8000/docs)

Для остановки:
```bash
docker compose down
```

---

### Вариант 2: Чистый Docker CLI (без Compose)

1. **Сборка образа:**
   ```bash
   docker build -t 112-simulator:latest .
   ```

2. **Запуск контейнера:**
   ```bash
   docker run -d \
     --name 112-simulator \
     -p 3000:3000 \
     -p 8000:8000 \
     -v $(pwd)/data:/app/data \
     --env-file .env \
     112-simulator:latest
   ```

## 💾 Сохранение данных (Data Persistence)

Папка `./data` монтируется внутрь контейнера по пути `/app/data`:
- База данных SQLite: `./data/112_simulator.db`
- Кэш аудио TTS: `./data/tts_cache/`
- Справочники и классификаторы: `./data/classifier_ekp.json`, `./data/moscow_112_addresses.json`

Все созданные билеты, результаты тестирования, сессии и пользователи сохраняются на диске хост-машины и не пропадут при пересоздании контейнера.

## ⚙️ Настройка конфигурации (`.env`)

Все параметры настраиваются в файле `.env`:
- `DATABASE_URL` — строка подключения к БД (по умолчанию SQLite).
- `SECRET_KEY` — ключ для подписи JWT токенов.
- `MOCK_LLM` — `True` (по умолчанию для автономной работы) или `False` для подключения реальных нейросетевых моделей.
- `OPENAI_API_KEY` / `DEEPSEEK_API_KEY` — ключи доступа к внешним LLM.
- `MOCK_TTS` — `True` (эмуляция синтеза речи) или `False` (подключение TTS сервиса).
