# Ограничения администратора

Роль ADMIN обслуживает комплекс и управляет учётными записями. Она не даёт
прав преподавателя: изменение сценариев, уроков, оценок, управление учебными
вызовами и действиями ДДС отклоняются сервером с HTTP 403.

## Данные и удаление

Администратор не может удалять билеты и документы базы знаний через API.
Удаление пользователя означает деактивацию с отзывом сессий; запись и история
обучения сохраняются. Физическое удаление критичных учебных данных для ADMIN
не предоставляется, в том числе после создания резервной копии. Отдельная
процедура «копия → подтверждение → физическое удаление» пока не реализована.
Существующая административная функция создания резервной копии сохранена.

## Базовая безопасность

Парольную политику, таймаут сессии и обязательность 2FA может менять только
ADMIN, чей логин входит в SECURITY_POLICY_ADMIN_USERNAMES (через запятую).
Если переменная отсутствует, право имеет INITIAL_ADMIN_USERNAME, по умолчанию
admin. Пустое значение запрещает изменение всем. Переменная задаётся в локальном
.env установки, а не через API управления пользователями.

Переключатель ENABLE_OPERATOR_112_FOR_LESSONS доступен всем ADMIN независимо
от этого дополнительного права. Обновление одного параметра не требует остальных.
Неизвестные ключи и некорректные значения отклоняются; весь пакет проверяется
до изменений. Изменения записываются в аудит SECURITY_POLICY_UPDATED.

## Персональные данные

ADMIN сохраняет список пользователей для управления учётными записями,
но не получает доступ к персональным ответам, оценкам, учебным сессиям,
именному рейтингу, учебным отчётам и рекомендациям ИИ. Агрегированные
аналитические показатели и технический мониторинг остаются доступны.
TEACHER получает через список пользователей только учеников своих групп
(учитываются cadet_ids и student_group_link). Секреты исключены схемой ответа.
Новые группы преподавателя получают teacher_id автоматически. Старые группы
без владельца не открывают преподавателям доступ ко всем ученикам автоматически.

Эти правила относятся к API приложения. Доступ владельца сервера к Docker,
БД и файлам регулируется отдельно средствами операционной системы.

## Исполнение и проверка

Были запущены четыре AGY/Gemini-воркера. Изменение списка пользователей
выполнил Gemini; три остальных участка не завершились из-за ограничений
инструментов AGY. Их реализацию и общую проверку завершил Codex.
Автоматические проверки находятся в tests/test_admin_restrictions.py.
