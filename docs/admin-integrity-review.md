# Независимая проверка Codex: требуется доработка

Проверка выполнена 17 октября 2026. Рабочие контейнеры не обновлялись.
Следующие проблемы подтверждены отдельными тестами Codex, а не только чтением кода.

## 1. Проверять эталон до чтения контролируемых файлов

`backend/core/integrity.py`: после JSON.parse проверяется только тип files.
Игнорируются schema_version/algorithm, пустой список, дубли, неверный формат
SHA-256, обязательные записи и безопасность путей.

Воспроизведено:

- Неизвестные версия/алгоритм и дублирующиеся записи принимаются как нормальный эталон.
- Если из эталона пропала запись backend/main.py и сам файл отсутствует,
  результат остаётся `ok`: контролируемая точка входа вообще не проверена.
- Эталон с `../outside.txt` заставляет checker читать файл вне root.
- Генератор принимает пустое дерево и создаёт эталон без обязательных файлов.

Нужна строгая валидация всей структуры перед хешированием файлов: поддерживаемая
версия/алгоритм, непустой список, уникальные канонические относительные пути,
ожидаемые типы/хеши/размеры, принадлежность области, обязательные точки входа.
Генератор также должен проверять обязательные файлы. Неверный эталон — unavailable,
без чтения внешних файлов и без ложного успеха.

Тесты: `tests/test_integrity_review.py`.

## 2. Проверять родительские каталоги и разрешённый root

Проверяется только `full_path.is_symlink()`, но любой родительский каталог
может оказаться symlink. При замене backend/api на ссылку на внешний каталог
с прежним содержимым checker читает внешние файлы и возвращает `ok`.

Перед чтением каждого файла проверять всю цепочку пути, фактический resolved path
и согласованную политику directory symlink. Не следовать за root. Ошибка/подмена
каталога должна давать отклонение, даже если байты внешнего файла совпадают.
Согласовать генерацию и проверку, сохранив необходимую поддержку native file symlink.

Тест: `test_parent_directory_symlink_is_not_followed_outside_root`.

## 3. Убирать текущий зелёный статус после неудачной повторной проверки

`frontend_react/app/admin/system/page.tsx`:

- Успешный healthcheck -> повторный запрос 503: остаётся «Сервер активен».
  Ветвь healthError срабатывает только при !health; старые данные health сохранены.
- Успешная проверка целостности -> повторный запрос 503: остаётся зелёное
  «Целостность подтверждена», потому что integrityResult сохраняется.

Приоритет ошибки/ожидания должен быть выше текущего зелёного статуса. Предыдущий
успешный результат можно оставить только как явно подписанную историю с временем,
не как подтверждение текущего состояния. Обработать эти сценарии и состояния
ожидания повторной проверки.

Тесты: `frontend_react/tests/admin_integrity_review.test.tsx`.

## Дополнительные замечания по объёму и качеству проверки

- В app/operator/page.tsx появилась миграция legacy operator_state_<ticketId>
  в состояние новой сессии. До задачи legacy-ключ удалялся. Это меняет изоляцию
  карточек между занятиями и не относится к TS/метрикам/целостности. Отделить
  это изменение от задачи; не переносить старую карточку в новую сессию ради
  прохождения старого теста. Аналогично отдельно обосновать восстановление поля
  фабулы в components/operator/left-panel.tsx.
- В vitest.config.mts глобальный testTimeout повышен с 5000 до 15000.
  Это изменение необходимо явно указать в отчёте: результаты тестов получены
  с новым лимитом. Не выдавать увеличение лимита за исправление причины зависания.
- Тест tutorial «calls onFinish ...» проверяет только typeof созданного mock,
  а не вызов onFinish. Дополнить реальным событием завершения/пропуска
  (допустим mock Joyride на границе библиотеки), проверить вызов и отсутствие
  завершения на обычном промежуточном событии.
- UI подписывает время integrity «UTC», но вызывает formatDate с локальным
  toLocaleString. Исправить подпись или форматирование и проверить часовой пояс.
