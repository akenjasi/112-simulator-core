## 1. Dual-Engine Architecture Overview

`StorageManager` in `backend/database.py` reads the `DATABASE_URL` environment variable at
startup and selects the appropriate engine:

| `DATABASE_URL` value              | Engine used | Dialect object          |
|-----------------------------------|-------------|-------------------------|
| `sqlite:///./dev.db` (default)    | SQLite 3    | `aiosqlite` / `sqlite3` |
| `postgresql+asyncpg://…`          | PostgreSQL  | `asyncpg`               |

The class exposes a unified async interface so all repository code is engine-agnostic.
Engine-specific differences are **contained to the schema layer only** — primarily:

| Concern         | PostgreSQL           | SQLite                                              |
|-----------------|----------------------|-----------------------------------------------------|
| UUID type       | `UUID`               | `TEXT` (stored as lowercase hex with dashes)        |
| JSON columns    | `JSONB`              | `TEXT` (JSON string, validated at app layer)        |
| Auto-timestamp  | `DEFAULT NOW()`      | `DEFAULT (datetime('now'))`                         |
| Boolean         | `BOOLEAN`            | `INTEGER` (0 / 1)                                   |
| Enum CHECK      | `CHECK (col IN …)`   | same (SQLite honours CHECKs from v3.25)             |

All schema snippets below show **PostgreSQL first**, with SQLite equivalents called out
in `-- SQLite:` comments.

## 2. `.env` Configuration

```dotenv
# ── Development / CI (default — no extra setup required) ──────────────────────
DATABASE_URL=sqlite+aiosqlite:///./dev.db

# ── Test isolation (in-memory, wiped after each test run) ────────────────────
DATABASE_URL=sqlite+aiosqlite:///:memory:

# ── Production (PostgreSQL) ───────────────────────────────────────────────────
DATABASE_URL=postgresql+asyncpg://simulator_user:s3cr3t@db.internal:5432/simulator_prod

# ── Local Docker Compose stack ────────────────────────────────────────────────
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/simulator_dev
```

### How `StorageManager` uses it

```python
# backend/database.py (abridged)
import os
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession
from sqlalchemy.orm import sessionmaker

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite+aiosqlite:///./dev.db")

engine = create_async_engine(
    DATABASE_URL,
    # SQLite needs check_same_thread disabled; asyncpg ignores this kwarg
    connect_args={"check_same_thread": False} if DATABASE_URL.startswith("sqlite") else {},
    echo=False,
)

AsyncSessionLocal = sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

class StorageManager:
    """Unified async storage interface — engine selected via DATABASE_URL."""
    ...
```

> **Note:** Never hard-code credentials. Use Docker secrets or a secrets manager in
> production.

## 3. UUID Convention

All primary keys are **version-4 UUIDs** generated by the application layer
(`uuid.uuid4()`) before insert.

```sql
-- PostgreSQL
user_id  UUID            PRIMARY KEY DEFAULT gen_random_uuid()

-- SQLite  (store as TEXT, app generates uuid4 string)
-- SQLite: user_id  TEXT  PRIMARY KEY
```

The application always generates the UUID; the `DEFAULT gen_random_uuid()` is a
safety net for raw SQL inserts in PostgreSQL only.

## 4. Domain 01 — Users & Groups

### 4.1 `users`

Stores all system principals: admins, teachers, and cadets.

```sql
-- ── PostgreSQL ────────────────────────────────────────────────────────────────
CREATE TABLE users (
    user_id                UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    username               VARCHAR(64) NOT NULL UNIQUE,
    password_hash          TEXT        NOT NULL,
    role                   TEXT        NOT NULL
                                       CHECK (role IN ('ADMIN', 'TEACHER', 'CADET')),
    full_name              TEXT,
    specialization         TEXT,                        -- e.g. "ПЦС", "ДСНС"
    group_ids              JSONB       NOT NULL DEFAULT '[]',   -- list[UUID str]
    last_login             TIMESTAMP WITH TIME ZONE,
    failed_login_attempts  INTEGER     NOT NULL DEFAULT 0,
    locked_until           TIMESTAMP WITH TIME ZONE,
    password_changed_at    TIMESTAMP WITH TIME ZONE,
    created_at             TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    is_active              BOOLEAN     NOT NULL DEFAULT TRUE
);

-- ── SQLite differences ────────────────────────────────────────────────────────
-- user_id               TEXT     PRIMARY KEY,          -- UUID as string
-- group_ids             TEXT     NOT NULL DEFAULT '[]', -- JSON array string
-- last_login            TEXT,                           -- ISO-8601 string
-- locked_until          TEXT,
-- password_changed_at   TEXT,
-- created_at            TEXT     NOT NULL DEFAULT (datetime('now')),
-- is_active             INTEGER  NOT NULL DEFAULT 1,    -- 0/1
```

**Field notes:**
- `group_ids` — denormalised list of `student_groups.group_id` values; kept in sync
  by the application whenever group membership changes.
- `locked_until` — set by auth middleware after `failed_login_attempts >= 5`.
- `specialization` — free-text dispatcher specialization used by the AI to tailor
  scenario generation.

### 4.2 `student_groups`

Logical cohort of cadets, owned by one teacher.

```sql
-- ── PostgreSQL ────────────────────────────────────────────────────────────────
CREATE TABLE student_groups (
    group_id    UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    group_name  TEXT        NOT NULL,
    department  TEXT,
    teacher_id  UUID        REFERENCES users (user_id) ON DELETE SET NULL,
    cadet_ids   JSONB       NOT NULL DEFAULT '[]',   -- list[UUID str]
    created_at  TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    is_active   BOOLEAN     NOT NULL DEFAULT TRUE
);

-- ── SQLite differences ────────────────────────────────────────────────────────
-- group_id    TEXT    PRIMARY KEY,
-- cadet_ids   TEXT    NOT NULL DEFAULT '[]',
-- created_at  TEXT    NOT NULL DEFAULT (datetime('now')),
-- is_active   INTEGER NOT NULL DEFAULT 1,
```

**Field notes:**
- `cadet_ids` — denormalised mirror of `users.group_ids`; source of truth for
  batch operations such as assignment creation.
- Deleting a teacher sets `teacher_id = NULL` (group is not removed).

### 4.3 `user_action_log`

Immutable audit trail of all security-relevant and pedagogical events.

```sql
-- ── PostgreSQL ────────────────────────────────────────────────────────────────
CREATE TABLE user_action_log (
    log_id         UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id        UUID    REFERENCES users (user_id) ON DELETE SET NULL,
    role           TEXT,
    action         TEXT    NOT NULL,    -- e.g. 'LOGIN', 'SCENARIO_CREATED', 'GRADE_OVERRIDE'
    target_entity  TEXT,               -- e.g. 'scenario_tickets', 'users'
    target_id      TEXT,               -- UUID of the affected record
    ip_address     TEXT,
    details        TEXT,               -- free-form JSON or human note
    timestamp      TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

-- ── SQLite differences ────────────────────────────────────────────────────────
-- log_id     TEXT  PRIMARY KEY,
-- user_id    TEXT  REFERENCES users (user_id),
-- timestamp  TEXT  NOT NULL DEFAULT (datetime('now')),
```

> **Design decision:** `ON DELETE SET NULL` preserves the audit trail even after a
> user account is hard-deleted. Prefer soft-deletion (`is_active = FALSE`) in normal
> operations.

## 5. Domain 02 — Scenario Tickets

### 5.1 `scenario_tickets`

Master record for every generated or imported 112-call scenario.

```sql
-- ── PostgreSQL ────────────────────────────────────────────────────────────────
CREATE TABLE scenario_tickets (
    scenario_id             UUID    PRIMARY KEY DEFAULT gen_random_uuid(),

    -- Workflow FSM state (pending -> draft -> approved -> archived)
    workflow_state          JSONB   NOT NULL DEFAULT '{}',

    -- Tunable generation parameters (difficulty, call_type, region, ...)
    settings                JSONB   NOT NULL DEFAULT '{}',

    -- Gold-standard expected answers used for automated grading
    ground_truth            JSONB   NOT NULL DEFAULT '{}',

    -- Raw AI-generated artefacts (transcript, tts_script, bricks_refs, ...)
    ai_content              JSONB   NOT NULL DEFAULT '{}',

    -- UUIDs of reference_materials linked to this scenario
    reference_material_ids  JSONB   NOT NULL DEFAULT '[]',

    -- Ordered list of {version, changed_by, changed_at, diff} objects
    version_history         JSONB   NOT NULL DEFAULT '[]',

    created_at              TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

-- ── SQLite differences ────────────────────────────────────────────────────────
-- scenario_id             TEXT  PRIMARY KEY,
-- workflow_state          TEXT  NOT NULL DEFAULT '{}',
-- settings                TEXT  NOT NULL DEFAULT '{}',
-- ground_truth            TEXT  NOT NULL DEFAULT '{}',
-- ai_content              TEXT  NOT NULL DEFAULT '{}',
-- reference_material_ids  TEXT  NOT NULL DEFAULT '[]',
-- version_history         TEXT  NOT NULL DEFAULT '[]',
-- created_at              TEXT  NOT NULL DEFAULT (datetime('now')),
```

**`workflow_state` shape (example):**
```json
{
  "current": "approved",
  "transitions": [
    {"from": "pending", "to": "draft",    "by": "<uuid>", "at": "2026-09-01T10:00:00Z"},
    {"from": "draft",   "to": "approved", "by": "<uuid>", "at": "2026-09-02T09:00:00Z"}
  ]
}
```

**`settings` shape (example):**
```json
{
  "call_type":   "fire",
  "region":      "Kyiv",
  "difficulty":  2,
  "language":    "uk",
  "caller_profile": {"age": 35, "emotional_state": "panic"},
  "time_limit_sec": 240
}
```

**`ground_truth` shape (example):**
```json
{
  "required_fields":   ["location", "victim_count", "fire_type"],
  "expected_services": ["ДСНС", "Швидка"],
  "keyword_phrases":   ["адреса", "кількість потерпілих"],
  "scoring_rubric":    {"location_accuracy": 20, "service_dispatch": 30, "tone": 10}
}
```

## 6. Domain 03 — Assignments & Sessions

### 6.1 `assignments`

Links scenarios (or card pools) to cadets or groups with scheduling metadata.

```sql
-- ── PostgreSQL ────────────────────────────────────────────────────────────────
CREATE TABLE assignments (
    assignment_id    UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
    scenario_id      UUID    REFERENCES scenario_tickets (scenario_id) ON DELETE SET NULL,
    card_pool_ids    JSONB   NOT NULL DEFAULT '[]',  -- for CARD_ACTIONS sessions
    session_type     TEXT    NOT NULL
                             CHECK (session_type IN ('CALL_SIMULATION', 'CARD_ACTIONS')),
    card_pool_source TEXT,               -- e.g. 'random', 'curated', 'import'
    mode             TEXT    NOT NULL DEFAULT 'TRAINING'
                             CHECK (mode IN ('TRAINING', 'EXAM')),
    group_id         UUID    REFERENCES student_groups (group_id) ON DELETE SET NULL,
    cadet_id         UUID    REFERENCES users (user_id) ON DELETE SET NULL,
    assigned_by      UUID    NOT NULL REFERENCES users (user_id) ON DELETE RESTRICT,
    available_from   TIMESTAMP WITH TIME ZONE NOT NULL,
    deadline         TIMESTAMP WITH TIME ZONE NOT NULL,
    is_active        BOOLEAN NOT NULL DEFAULT TRUE
);

-- ── SQLite differences ────────────────────────────────────────────────────────
-- assignment_id    TEXT     PRIMARY KEY,
-- scenario_id      TEXT     REFERENCES scenario_tickets (scenario_id),
-- card_pool_ids    TEXT     NOT NULL DEFAULT '[]',
-- group_id         TEXT     REFERENCES student_groups (group_id),
-- cadet_id         TEXT     REFERENCES users (user_id),
-- assigned_by      TEXT     NOT NULL REFERENCES users (user_id),
-- available_from   TEXT     NOT NULL,
-- deadline         TEXT     NOT NULL,
-- is_active        INTEGER  NOT NULL DEFAULT 1,
```

**Constraints:**
- Exactly one of `group_id` or `cadet_id` must be non-null (enforced at app layer).
- `scenario_id` is null for `CARD_ACTIONS` sessions that draw from a pool only.

### 6.2 `exam_sessions`

Runtime state for a live `CALL_SIMULATION` session (training or exam).

```sql
-- ── PostgreSQL ────────────────────────────────────────────────────────────────
CREATE TABLE exam_sessions (
    session_id      UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
    session_type    TEXT    NOT NULL,   -- always 'CALL_SIMULATION' here
    assignment_id   UUID    NOT NULL REFERENCES assignments (assignment_id) ON DELETE RESTRICT,
    cadet_id        UUID    NOT NULL REFERENCES users (user_id) ON DELETE RESTRICT,
    status          TEXT    NOT NULL,   -- 'pending' | 'active' | 'paused' | 'completed' | 'aborted'

    -- Snapshot of the browser-side call UI state (call_active, muted, ...)
    browser_call    JSONB   NOT NULL DEFAULT '{}',

    -- Live FSM state (current_phase, hints_shown, timer_elapsed, ...)
    dynamic_state   JSONB   NOT NULL DEFAULT '{}',

    -- Ordered list of {role, text, timestamp, audio_url} turn objects
    dialogue_log    JSONB   NOT NULL DEFAULT '[]',

    -- Events queued while the cadet was offline (for reconnect replay)
    offline_buffer  JSONB   NOT NULL DEFAULT '[]',

    start_time      TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    end_time        TIMESTAMP WITH TIME ZONE
);

-- ── SQLite differences ────────────────────────────────────────────────────────
-- session_id      TEXT  PRIMARY KEY,
-- assignment_id   TEXT  NOT NULL REFERENCES assignments (assignment_id),
-- cadet_id        TEXT  NOT NULL REFERENCES users (user_id),
-- browser_call    TEXT  NOT NULL DEFAULT '{}',
-- dynamic_state   TEXT  NOT NULL DEFAULT '{}',
-- dialogue_log    TEXT  NOT NULL DEFAULT '[]',
-- offline_buffer  TEXT  NOT NULL DEFAULT '[]',
-- start_time      TEXT  NOT NULL DEFAULT (datetime('now')),
-- end_time        TEXT,
```

## 8. Domain 05 — Bricks Matrix

### 8.1 `bricks_matrix_refs`

One-to-one extension of `scenario_tickets` tracking TTS compilation state.

```sql

);

-- ticket_id    TEXT     PRIMARY KEY REFERENCES scenario_tickets (scenario_id),
```

### Import validation rules

| Field                    | Rule                                                                    |
|--------------------------|-------------------------------------------------------------------------|
| `scenario_id`            | Optional — server generates `uuid4()` if absent                        |
| `settings`               | **Required.** Must contain `call_type`, `region`, `difficulty`         |
| `ground_truth`           | **Required.** Must contain `scoring_rubric` with numeric values        |
| `workflow_state`         | Defaults to `{"current": "pending", "transitions": []}`                |
| `ai_content`             | Optional — can be populated later via AI generation pipeline           |
| `bricks_matrix`          | Optional — if present, inserts a row in `bricks_matrix_refs`           |

Rows that fail validation are recorded in `import_jobs.errors` and **do not halt** the
rest of the import. The `failed_count` counter is incremented per rejected row.

## 12. EXAM Mode vs TRAINING Mode

The `mode` column on `assignments` controls session behaviour across the entire stack.

| Behaviour                      | `TRAINING`                              | `EXAM`                                                      |
|--------------------------------|-----------------------------------------|-------------------------------------------------------------|
| **Hints**                      | Available on demand                     | **Disabled** — hint API returns 403                         |
| **Time limit**                 | Advisory (warning shown, not enforced)  | **Hard cutoff** — session auto-closes at `time_limit_sec`   |
| **Re-attempt**                 | Allowed (teacher configures count)      | **Prohibited** — one attempt per assignment                 |
| **Pause**                      | Allowed                                 | **Prohibited** — pausing is treated as abort                |
| **Score visibility (cadet)**   | Shown immediately after completion      | **Hidden** until teacher publishes report                   |
| **Report flag**                | `is_attestation = FALSE`                | `is_attestation = TRUE` — archived as official record       |
| **Audit trail**                | Standard                                | Every action logged with millisecond timestamp              |
| **AI feedback**                | Shown inline during session             | **Suppressed** until report publication                     |
| **Export**                     | Teacher can export at any time          | Export locked until `is_attestation` report is signed       |

### Application-layer enforcement points

1. **Session creation** (`POST /api/v2/sessions`): reads `assignments.mode` and sets
   `exam_sessions.dynamic_state.exam_mode = true` if applicable.

2. **Hint endpoint** (`GET /api/v2/sessions/{id}/hint`): returns `403 Forbidden` when
   `dynamic_state.exam_mode == true`.

3. **Timer service** (`backend/services/timer.py`): subscribes to the session WebSocket
   channel; fires `SESSION_TIMEOUT` event at `time_limit_sec` in exam mode.

4. **Report generation** (`POST /api/v2/reports`): sets `is_attestation` based on
   `assignment.mode` at report creation time (immutable afterwards).

5. **Re-attempt guard** (`POST /api/v2/sessions`): queries `exam_sessions` for an
   existing completed session with the same `(assignment_id, cadet_id)` pair; rejects
   with `409 Conflict` if `assignment.mode == 'EXAM'`.

## 13. Legacy v1 Tables & v2 Prefix Convention

`backend/database.py` was shipped with an initial set of tables that remain in
production databases:

| Legacy (v1) table    | Status          | Notes                                                   |
|----------------------|-----------------|---------------------------------------------------------|
| `users`              | **Kept as-is**  | v2 extends with new columns via `ALTER TABLE`            |
| `evaluation_results` | **Kept as-is**  | v2 adds `grammar`, `errors_list` columns via migration  |
| `incident_cards`     | **Kept as-is**  | v2 adds `card_origin`, `assigned_services` columns      |
| `audit_logs`         | **Renamed**     | Maps to `user_action_log`; old name kept as a VIEW      |

### Migration strategy for shared tables

For tables that exist in both v1 and v2 (e.g. `users`, `incident_cards`,
`evaluation_results`), use **additive `ALTER TABLE` migrations** rather than
dropping and recreating:

```sql
-- Example: add v2 columns to legacy users table
ALTER TABLE users ADD COLUMN IF NOT EXISTS specialization    TEXT;
ALTER TABLE users ADD COLUMN IF NOT EXISTS group_ids         JSONB NOT NULL DEFAULT '[]';
ALTER TABLE users ADD COLUMN IF NOT EXISTS locked_until      TIMESTAMP WITH TIME ZONE;
ALTER TABLE users ADD COLUMN IF NOT EXISTS password_changed_at TIMESTAMP WITH TIME ZONE;

-- SQLite (no IF NOT EXISTS before 3.37; wrap in try/except at app layer):
-- ALTER TABLE users ADD COLUMN specialization       TEXT;
-- ALTER TABLE users ADD COLUMN group_ids            TEXT NOT NULL DEFAULT '[]';
-- ALTER TABLE users ADD COLUMN locked_until         TEXT;
-- ALTER TABLE users ADD COLUMN password_changed_at  TEXT;

-- Example: add v2 columns to legacy incident_cards
ALTER TABLE incident_cards ADD COLUMN IF NOT EXISTS card_origin       TEXT NOT NULL DEFAULT 'ai_generated';
ALTER TABLE incident_cards ADD COLUMN IF NOT EXISTS assigned_services JSONB NOT NULL DEFAULT '{}';

-- Example: add v2 columns to legacy evaluation_results
ALTER TABLE evaluation_results ADD COLUMN IF NOT EXISTS grammar     JSONB NOT NULL DEFAULT '{}';
ALTER TABLE evaluation_results ADD COLUMN IF NOT EXISTS errors_list JSONB NOT NULL DEFAULT '[]';
```

### Purely new v2 tables

Tables with no v1 counterpart are created fresh and carry **no prefix**
(they are the canonical v2 schema from the start):

`student_groups`, `assignments`, `exam_sessions`, `card_action_sessions`,
`reference_materials`, `session_reports`, `ai_insights`, `sla_tasks`,
`bricks_matrix_refs`, `import_jobs`

### `audit_logs` compatibility view

```sql
-- Keeps existing v1 queries working while data flows into user_action_log
CREATE VIEW audit_logs AS
SELECT
    log_id    AS id,
    user_id,
    action,
    details,
    timestamp AS created_at
FROM user_action_log;
```

## 14. Recommended Migration Path

### Phase 1 — Local Development (SQLite, always)

- Zero setup: `DATABASE_URL` defaults to `sqlite+aiosqlite:///./dev.db`.
- Run `python backend/database.py --init` (or the Alembic equivalent) to create all
  tables in the local file.
- Use SQLite for all unit and integration tests (`:///:memory:` for isolation).
- **Stay on SQLite** as long as the team is ≤ 3 developers and the dataset fits on one
  machine (typically < 50 k session rows).

### Phase 2 — Staging / QA (PostgreSQL via Docker Compose)

Switch when any of the following applies:
- JSONB path queries become necessary for analytics (e.g. `workflow_state->>'current'`).
- Concurrent write load causes SQLite lock contention (> 5 simultaneous sessions).
- You need row-level locking, `FOR UPDATE SKIP LOCKED` for the job queue, or
  `LISTEN/NOTIFY` for WebSocket fan-out.

```yaml
# docker-compose.yml excerpt
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: simulator_user
      POSTGRES_PASSWORD: s3cr3t
      POSTGRES_DB: simulator_dev
    volumes:
      - pg_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
```

Migration steps:
1. Set `DATABASE_URL=postgresql+asyncpg://simulator_user:s3cr3t@localhost:5432/simulator_dev`.
2. Run `alembic upgrade head` to create all v2 tables in PostgreSQL.
3. (Optional) Migrate existing SQLite data with `pgloader` or a one-off script.

### Phase 3 — Production (Managed PostgreSQL)

Use when:
- The system is deployed to a cloud environment (GCP Cloud SQL, AWS RDS, Supabase, etc.).
- You need point-in-time recovery, read replicas, or connection pooling (PgBouncer).
- The team requires role-based DB access (separate read-only credentials for
  reporting queries).

Checklist before switching:
- [ ] All GIN indexes applied (see §10).
- [ ] `DATABASE_URL` injected via environment secret — never committed to source.
- [ ] Alembic migration history is clean (`alembic current` shows `head`).
- [ ] Connection pool size tuned (`pool_size=10, max_overflow=20` for asyncpg).
- [ ] `pg_stat_statements` enabled for slow-query monitoring.
- [ ] Nightly logical backup (`pg_dump`) verified with a restore drill.

> **Do NOT switch to PostgreSQL mid-session** without a maintenance window.
> SQLite to PostgreSQL is a one-way migration for the session and evaluation tables.
