## Состояние исходников и границы изменений

- Исходная ветка — `feat/dds-phone-training`, исходный HEAD — `45da606`. Перед аудитом рабочая копия содержала значительные пользовательские изменения DDS, телефона и профиля; они не приписываются аудитору.
- Контрольный коммит **`d51076c`** (`chore: preserve pre-audit workspace and evidence baseline`) сохраняет исходную работу пользователя и первоначальный аудит. Исправления выполнены после него, в отдельной ветке.
- Финальный коммит исправлений **пока не создан**. Первое `git add -A` прошло, последующее добавление окончательных доказательств не выполнилось: автоматическая проверка разрешений исчерпала лимит использования. Это технический отказ проверки, не решение о небезопасности Git. Часть последних изменений отчёта/логов остаётся unstaged; все файлы сохранены в рабочей копии. Никакой обход проверки не предпринимался. Для передачи исходников учитывайте и index, и working tree, а не только HEAD.
- Внешние push, PR, merge, live deploy и изменение рабочих сервисов/данных не выполнялись. PostgreSQL-проверки и HTTP/TLS smoke использовали собственные одноразовые контейнеры/сети; реальная SQLite читалась только при первоначальной проверке схемы.
- Тесты `tools_tests/test_*.py` и независимые acceptance manifests не менялись. В `tools_tests/requirements.txt` актуализирован только инструментарий для Python 3.11 и добавлен email-validator, необходимый историческому тесту с Pydantic EmailStr.

## Удаление и упрощение

- `frontend_react/out` исключён из tracking, локальный output сохранён; свежая сборка в image подтверждена. Уверенность высокая: это generated export. Условие безопасной поставки — обязательный build, не копирование произвольного старого out.
- TLS key/cert исключены из tracking, локальные файлы сохранены. Уверенность высокая для запрета общих секретов, но полная безопасность требует ротации уже распространённого ключа. Сам факт удаления из index этого не делает.
- Семь ad hoc patch/check scripts переведены в `docs/archive/one-off-scripts/*.py.txt` с исходными байтами. Безопасная замена для схемы — `python -m scripts.schema` (read-only по умолчанию, `--apply` явный). Архив не исполнять как универсальный updater.
- Passlib/psycopg2/sip.js/неиспользуемая Vercel analytics dependency удалены после проверки исполняемых imports/build. SIP функциональность не признана ненужной — зафиксирован статус неполной реализации. Полезный shadcn CSS сохранён с лицензией; antd/icons восстановлены, поскольку прямые imports есть.
- Альтернативный database module сохранён как compatibility re-export единого engine. Три поколения билетов, два runtime-пути, локальное демо и пользовательские модели не удалялись: безопасного доказательства отсутствия потребителей нет. Их объединение требует отдельной миграции данных/контрактов.

## Непроверенные области и причины

1. **Живые ASR/TTS/classifier/GPU и качество речи/LLM.** Базовый runtime намеренно не устанавливает тяжёлый ML; стандартные GGUF/сервисные пути не подготовлены как приёмочный стенд. Текстовые нормализаторы и контролируемый отказ проверены, native subprocess Qwen в диагностике падает. GPU/runtime/model quality, микрофон, autoplay и WebAudio в настоящем браузере не проверялись.
2. **SIP/PBX/SOAP/LDAP.** Не предоставлены реальные endpoints/аккаунты/физические телефоны. Проверены границы доступа и честная unavailable/simulation семантика, не доставка вызова или интеграционного сообщения.
3. **Нагрузка, HA и альтернативные платформы.** Не измерялись 100 пользователей, 20 вызовов, latency SLA, memory/CPU при длительной нагрузке, Windows/mobile browsers. Однопроцессный режим обязателен; multiworker/replica не доказаны.
4. **Целевая эксплуатация.** Не выполнялись live deploy, миграция действующей PG, переключение реальной БД, ротация распространённого TLS, внешнее резервирование, drill реального рабочего дампа и полный выпуск/перенос offline bundle на другой хост. Проверены builds, fail-fast release и изолированное восстановление.
5. **Supply chain.** Нет независимого provenance/signature-аудита native binaries/GGUF, container OS CVE/SBOM и полного optional ML graph. Docker base tags не зафиксированы digest; hash lock относится к базовому Python графу выбранной платформы. Нулевой advisory-результат — снимок баз данных уязвимостей на момент проверки, не гарантия безопасности.
6. **Удалённый CI/настройки репозитория.** GitHub Actions/branch protection не проверялись через удалённый сервис; локальные команды не называются удалённой приёмкой. Финальный Git commit ограничен техническим отказом автоматического approval review из-за usage limit.
7. **Исчерпывающий E2E/pen test.** Проверки модулей, REST/WS и контейнеров не заменяют ручной полный браузерный сценарий на всех ролях или формальную проверку всей поверхности. Исторические positive сценарии из LEGACY_TESTS требуют дальнейшей контрактной приёмки; их нельзя объявлять лишними только из-за 401/403.

## Порядок дальнейшей эксплуатационной приёмки

Это внешние испытания и ограничения, заранее отделённые планом от локальных исправлений; они не объявлены пройденными.

1. Завершить Git-оформление после восстановления automatic approval review; проверить diff от `d51076c`, включая последние unstaged отчёты, и выполнить весь обязательный gate при новых изменениях.
2. На выделенном стенде проверить ротацию ключей/паролей, владельцев старых volumes, backup реальной БД и поддерживаемость её схемы. Только затем планировать переключение установки.
