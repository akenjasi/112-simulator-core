# Открытые задачи и проверки

Статус: единый список незавершённых работ и непроверенных требований, 19.10.2026. Это не инструкция немедленно реализовать все пункты. Выполненные задачи удаляются из активного списка после проверки; существенные решения остаются в истории/коммите.

| ID | Что требуется | Текущее основание и критерий закрытия |
|---|---|---|
| OPS-02 | Ротация опубликованных TLS/паролей | Наличие certs в истории нельзя устранить переносом документа. Владелец установки заменяет распространённые пары/пароли и проверяет доверие клиентов |
| OPS-03 | Рабочий restore/retention/RPO/RTO | Изолированный PostgreSQL check не заменяет восстановление реальной копии; отдельная внешняя копия файлов/БД, retention, документированный drill и проверенные сроки |
| OPS-04 | Нагрузка, HA и несколько процессов | DDS report worker однопроцессный. Требуются отдельная координация/испытания прежде, чем обещать HA,100 пользователей/20 вызовов или норматив latency |
| ML-01 | Приёмка нейроотчёта на настоящей модели | Запустить подготовленный runtime, проверить health и синтетическую генерацию, таймаут/контекст/качество без реальных персональных данных. Исторические mock tests не доказывают inference |
| ML-02 | Голос/ASR/classifier | Базовый runtime не включает все native/ML weights и отдельные сервисы. Нужны явный поддерживаемый режим, модели/бинарники, реальные WAV/микрофон/распознавание и качество; не включать функцию одним обещанием в README |
| INT-01 | Реальные PBX/SPO112/LDAP | Проверить контракты, права, отказ внешнего сервиса и наблюдаемый внешний результат на предоставленном стенде. Наличие адаптера/эндпоинта недостаточно |
| INT-02 | Генератор плана телефонного упражнения | Текущий [телефонный цикл](product/dds-phone-training.md) принимает явно подготовленный источник. Согласованные контакты, реплики и ключи проверки генератора требуют отдельной интеграции и приёмки |
| DATA-01 | Старые форматы/engine/сидеры | Не объединять модели и DB engines без миграции. Демонстрационные сидеры предназначены только для нового SQLite-файла; существующие БД/PG отклоняются. Миграция всех исторических форматов требует отдельной приёмки |
| QA-01 | Полный исторический suite | Core и полный backend-all различаются. Проверить старые роли/auth/данные/форматы, не ослабляя права и независимые проверки ради зелёного результата |
| QA-02 | Согласовать исторический frontend scope guard | На main `ea845fc` неизменённый `tools/tests/acceptance/test_dds_frontend_scope.py` обнаруживает 14 расхождений с прежним baseline, включая телефонное упражнение и обновлённые зависимости. Требуется независимое решение владельца приёмки; эта уборка не меняет guard/baseline или продуктовый frontend |
| QA-03 | Стабилизировать завершение frontend-тестов | В некоторых полных прогонах после успешных assertions возникают поздние React callbacks `window is not defined`, отнесённые Vitest к admin_panel.test.tsx. Есть полностью успешные прогоны; исходная копия также проходила, причина нестабильности пока не установлена. Сохранить проверки и обработку unhandled errors, локализовать завершение async-работы отдельным исправлением |
| UI-01…UI-05 / THEME-01 | Визуальная приёмка замечаний 18.10 | Имя/статус в карточке, кнопка запуска, прогресс, диалог выбора, split-screen и обе темы на целевых ширинах; реализация и прежние скриншоты не означают подтверждение пользователя |
| FLOW-01…FLOW-04 | Приёмка полного teacher/cadet пути | Реальные статусы занятий, понятный разбор/оценка, единые подписи билетов и явный импорт существующих учащихся. Сверить текущий UI с кодом и пройти сценарий двумя ролями |
| OLD-06/OLD-07 | Админское разблокирование/проверка оборудования | Проверить реальное снятие lockout и объяснимость VoIP-кнопки для DDS. Старое упоминание проблемы не доказывает её наличие после последних изменений |
| PROD-01 | Асинхронные домашние модули | Отдельная идея из старого backlog: пакет заданий без live-преподавателя. Не считать существующую самотренировку полным выполнением требования |
| PROD-02 | Целевой подбор «работы над ошибками» | Следующая тренировка уже доступна; автоматический выбор только проблемных категорий должен подтверждаться отдельным контрактом и данными |
| PROD-03 | Периодические AI-рекомендации | Идея ночного batch вместо задержки каждого запроса; определить расписание/очередь/ошибки перед реализацией, не путать с текущим persisted report job |
| REQ-01 | Уточнить старые SLA/нормативные обещания | В прежних заданиях были разные нормативы времени реагирования, мобильность, шифрование и формальные требования. Только утверждённый актуальный контракт и измерение на стенде позволяют закрыть их; источники не подтверждают соответствие |

Задачи тестировщика FIX-01…FIX-10 уже имеют результаты независимого ревью: [историческое свидетельство](history/2026-10-19/tester-fixes-review.md). Их не нужно запускать повторно как десять новых поручений. В частности, удалённые heatmap/radar, обязательный номер наряда и явный EXAM timeout не возвращаются по старому prompt. Остаточная живая приёмка вынесена в пункты выше.

Область и приоритет следующей реализации определяются текущим поручением пользователя. Старые назначения Gemini/Antigravity, запреты commit из старой задачи и роли техлида не переносятся автоматически.
