# Жизненный цикл урока ДДС (DDS Lesson Cycle)

Документация серверного жизненного цикла практического занятия по роли «Диспетчер ДДС» (Задача А-06).

---

## 1. Архитектура и этапы цикла

Жизненный цикл урока ДДС объединяет преподавателя (Teacher) и учебную группу курсантов (Cadets):

```
       [ Преподаватель ]
              │
              ▼
1. Создание урока (POST /api/v1/lessons)
   - target_role: DISPATCHER_DDS
   - ticket_id: ScenarioTicket.scenario_id (поле запроса; хранится в Assignment.scenario_id)
   - group_id: группа своего преподавателя
   - статус: WAITING
              │
              ▼
2. Старт урока (POST /api/v1/lessons/{id}/start)
   - Транзакционная блокировка (UPDATE assignments SET status=status ...)
   - Валидация билета и активных курсантов (N участников)
   - Каждому курсанту создается пара: ExamSession(CARD_ACTIONS) + IncidentCard(card_origin=DDS)
   - В ExamSession.dynamic_state['dds'] сохраняется неизменяемый входящий снимок
   - Идемпотентный replay: повторный вызов в ACTIVE возвращает сохраненный срез без повторных записей
   - Статус урока: ACTIVE
              │
              ├─────────────────────────────────────────┐
              ▼                                         ▼
   [ Курсант 1 (Cadet 1) ]                   [ Курсант N (Cadet N) ]
   - Получение сессии                        - Получение сессии
     GET /api/dds/sessions/{id}                GET /api/dds/sessions/{id}
   - Выполнение действий                     - Выполнение действий
     POST /api/dds/sessions/{id}/actions       POST /api/dds/sessions/{id}/actions
   - Завершение работы                       - Завершение работы
     POST /api/dds/sessions/{id}/finish        POST /api/dds/sessions/{id}/finish
              │                                         │
              └────────────────────┬────────────────────┘
                                   │
                                   ▼
3. Остановка урока (POST /api/v1/lessons/{id}/stop)
   - Фиксация completed_at, статус COMPLETED
   - Незавершённые работы отображаются как INCOMPLETE; в БД сессия закрывается как COMPLETED со stopped_at и submitted_at=None
   - Идемпотентный replay: повторный вызов stop сохраняет оригинальный completed_at
   - Честная статистика в отчетах без вымышленных оценок и без фиктивных билетов
```

## 3. Спецификация API ДДС

### 3.1 Каталог билетов
`GET /api/dds/tickets`
- **Доступ**: `ADMIN`, `TEACHER` (`CADET` получает 403 Forbidden).
- **Ответ**: Список билетов, пригодных для ДДС (`content.incoming_card` с непустым описанием и службами). Скрытые эталоны удалены.
```json
[
  {
    "ticket_id": "b3e04746-86c8-47bc-873b-e3c3b03f0b2a",
    "title": "Пожар в жилом секторе"
  }
]
```

### 3.2 Назначенные сессии курсанта
`GET /api/dds/assignments`
- **Доступ**: `CADET` (только свои сессии), `ADMIN`.
- **Ответ**: Список активных сессий ДДС текущего пользователя с полным снимком состояния.

### 3.3 Состояние сессии
`GET /api/dds/sessions/{session_id}`
- **Доступ**: `CADET` (владелец), `TEACHER` (автор урока), `ADMIN`.
- **Ответ**:
```json
{
  "session_id": "a1b2c3d4-...",
  "lesson_id": "e5f6g7h8-...",
  "ticket_id": "b3e04746-...",
  "card_id": "c9d8e7f6-...",
  "session_status": "ACTIVE",
  "lesson_status": "ACTIVE",
  "incoming_card": { ... },
  "actions": [ ... ],
  "submitted_at": null,
  "score": null
}
```

### 3.4 Выполнение действий
`POST /api/dds/sessions/{session_id}/actions`
- **Доступ**: `CADET` (только владелец сессии).
- **Идемпотентность**: `request_id` обязателен. Повторный запрос с идентичным payload возвращает `200 OK` и текущее состояние. Повтор того же `request_id` с измененным телом возвращает `409 Conflict`.
- **Пример тела (обновление статуса)**:
```json
{
  "request_id": "req-uuid-001",
  "kind": "status",
  "service_name": "Пожарная охрана",
  "status": "Прибытие",
  "comment": "Первый расчет на месте"
}
```
- **Пример тела (передача / dispatch)**:
```json
{
  "request_id": "req-uuid-002",
  "kind": "dispatch",
  "service_name": "Скорая помощь",
  "who_accepted": "Диспетчер подстанции 14",
  "summary": "Передана учебная карточка, направление бригады подтверждено",
  "order_number": "14-08"
}
```
- **Защита данных (LLM Safe)**: Произвольный текст курсанта (`comment`, `summary`, `who_accepted`, `order_number`) и идентификатор пользователя (`actor_id`) сохраняются исключительно в защищенном журнале `session.dynamic_state['dds']['actions']`. В карточку `card.assigned_services` записываются только безопасные метаданные (`status`, `kind`, `at`), исключая передачу персональных текстов во внешний LLM-контекст оценки.

### 3.5 Завершение работы
`POST /api/dds/sessions/{session_id}/finish`
- **Доступ**: `CADET` (только владелец сессии).
- **Поведение**: Фиксирует `submitted_at`, переводит `ExamSession.status` в `COMPLETED`. Повторные вызовы идемпотентны. Если урок уже остановлен преподавателем (`COMPLETED`) до завершения курсантом, возвращает `409 Conflict`.

## 4. Изоляция и защита устаревших маршрутов (Guards)

Для назначенных уроков ДДС старые маршруты блокируются с кодом `409 Conflict` для сохранения целостности состояния:
1. `POST /api/dds/action` и `POST /api/dds/cards/{id}/action`: Запрещены для карточек назначенных сессий ДДС; требуют использования `/api/dds/sessions/{id}/actions`.
2. `POST /api/v1/sessions/{id}/evaluate` и `/api/v2/sessions/{id}/submit_card`: Запрещены для назначенных сессий ДДС.
3. `POST /api/v2/assignments/{id}/sessions/start`: Запрещен для назначений с ролью `DISPATCHER_DDS`.
4. `POST /api/v2/sessions/{id}/message`: Запрещен диалоговый LLM-чат для сессий ДДС.
5. `PATCH /api/v2/ticket-results/{id}/appeal` и `PATCH /api/v1/analytics/records/{id}/appeal`: Отклоняются с `409 Conflict` для результатов назначенных сессий ДДС.
6. `GET /api/v1/lessons/{id}` и `/stats`: Курсанты изолированы (`403 Forbidden`), чтобы исключить просмотр действий и результатов одногруппников.

## 5. Честная статистика и оценки

1. **Отсутствие вымышленной шкалы**: Сервер не генерирует произвольных оценок («100 баллов по умолчанию» или «автоматический зачет»). Оценка присутствует только в том случае, если в базе данных сохранен валидный результат `EvaluationResult` или `TicketResult` (конечные числа в диапазоне 0..100 с сохранением дробей и значения 0.0).
2. **Множественные карточки (Legacy support)**: Для исторических сессий с несколькими карточками каждая карточка представляется отдельным элементом `tickets` без создания фиктивного идентификатора `ticket-dds`. Оценка курсанта рассчитывается как среднее реальных оценок карточек.
3. **Фиксация состава группы**: После старта урока состав участников фиксируется по фактическим сессиям. Изменение группы или очистка ее состава после старта не ломает повторный запуск (replay) и исторические отчеты.

## Проверки и границы приёмки

Независимые тесты написаны GPT-техлидом: 31 passed на SQLite/Python3.14 и 31 passed на PostgreSQL15/Python3.11; дополнительно 104 passed регрессии отчётов и авторизации на PostgreSQL15. Проверяются N=2/N=5, повторы/параллельные запросы, доступ, сохранность действий, неизменность входящих данных, чтение нулевых и дробных оценок, исторические неполные данные и защита legacy-обходов.

Новая шкала и автоматическое оценивание ДДС не реализованы. Выполнение без оценки показывается как «нет оценки». Максимальная нагрузка не измерена. Качество свободного текста Qwen требует проверки преподавателем; статус completed означает сохранённый ответ модели. Облачное демо требует отдельной подготовки и приёмки. Браузерная приёмка текущего UI на момент этой записи ещё выполняется.

### Граница нейроотчёта без оценки

Цикл А-06 может завершиться без `EvaluationResult` и `TicketResult`: новая методика оценивания отложена. Существующий генератор А-03 в таком случае сохраняет отказ `insufficient_data` **до обращения к Qwen**, даже если карточки и действия есть. Это не потеря действий и не результат генерации. Повтор без появления результатов оценивания не устраняет причину отказа. Отчёт наблюдений только по действиям потребует отдельного изменения контракта генератора; А-06 не создаёт фиктивных оценок ради его запуска.

В браузерной проверке с двумя реальными входами обучаемых проверены сохранённый снимок этого занятия, данный отказ и его восстановление после reload. Успешный Qwen-отчёт по новому неоценённому занятию не получен. Качество свободного текста Qwen и облачная демонстрация остаются отдельными непринятыми этапами. Старые общие дашборды и профиль обучаемого не входят в приёмку истории конкретного занятия А-06.
