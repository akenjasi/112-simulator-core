# Данные занятия для нейроотчёта ДДС

Первый backend-этап нейроотчёта преподавателя. Генерация текста LLM и интерфейс запуска отчёта подключаются отдельно.

## API

`GET /api/ai-analytics/lessons/{lesson_id}/data`

Требуется Bearer-токен. ADMIN получает данные любого занятия; TEACHER — только назначенного им занятия. Остальные роли получают 403, отсутствие токена — 401. Неизвестное занятие — 404; незавершённое занятие или целевая роль, отличная от DISPATCHER_DDS, — 409.

Ответ содержит сведения о занятии, фактических исторических участниках, завершённых сессиях, сохранённых карточках/действиях, оценках, результатах билетов, отдельные счётчики сущностей и предупреждения о недостающих данных. Выборка ограничена точным lesson_id и его завершёнными сессиями. Пустые данные не подменяются другими группами или занятиями. Поле filled_data карточки с данными заявителя не включается. Сохранённые комментарии и история действий остаются учебными данными; передавая их LLM, следует трактовать их как данные, а не инструкции.

Endpoint не вызывает LLM, не выставляет оценки и не создаёт нейроотчёты. Старые сборщики аналитики не переключаются на этот сервис автоматически. Это необходимо сделать отдельным этапом интеграции.

## Проверки

Запускать с отдельной тестовой БД через DATABASE_URL, не с базой работающего учебного стенда:

```sh
python3 -m pytest -q tests/test_dds_report_data_acceptance.py tests/test_dds_report_data_unit.py
```

Проверены изоляция разных занятий/групп, права доступа, исторические участники, исключение активных сессий и данных заявителя, пустые данные, отсутствие вызовов LLM и записи советов.

Результаты приёмки 17.10.2026:

- 10 новых тестов и 9 целевых регрессий аналитики/авторизации прошли на SQLite.
- Все 10 новых тестов прошли на PostgreSQL 15 в Docker/Python 3.11 с зависимостями backend-образа.
- В PostgreSQL-проверке использован тестовый NullPool: существующие pytest-фикстуры создают разные event loop, между которыми нельзя переиспользовать соединения asyncpg. Конфигурация runtime и общие фикстуры проекта не менялись.

Исходная реализация выполнена через Antigravity (Gemini 3.8 Flash High); diff и независимые приёмочные тесты проверены отдельно. Инференс модели, генерация билетов, UI, схемы БД и работающий стенд в этом изменении не затрагиваются.
