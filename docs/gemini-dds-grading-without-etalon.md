# Понятное оценивание ДДС без искусственного эталона

## 1. Концепция и актуальное решение пользователя

В сценарии работы диспетчера ДДС курсант получает готовую карточку происшествия со службами и выполняет действия по ней (приём вызова, смену статусов реагирования, фиксацию комментариев и сведений о передаче сообщений дежурным нарядам).
Отдельный искусственный «эталон действий ДДС» (ожидаемое решение, этапы, результат, норматив подтверждения, образцовый комментарий) отменён. Преподавателю больше не нужно вручную заполнять или генерировать эти поля.

Разбор работы курсанта ДДС строится на основе **4 понятных блоков**:
1. **Исходная карточка происшествия (контекст задания)** — то, что получил курсант: суть вызова, адрес, заявитель, описание, распределение по службам, важные признаки и факты. Карточка отображается содержательно и по-русски, без сырых технических ключей (`fio`, `phones`, `aon`, `statuses`, `visClass`, `bricks`, css-классов и т.д.).
2. **Действия курсанта** — хронология фактических действий курсанта по карточке: служба, статус/этап, дословный комментарий, сведения о передаче сообщений (кто принял, номер наряда, краткое содержание). Если действий нет или они не привязались к работе — честно и спокойно показывается «Сохранённые действия для этой работы отсутствуют».
3. **Оценка и замечания преподавателя (Экспертная оценка)** — балл преподавателя 0–100 (с поддержкой дробных чисел), развёрнутый комментарий/замечания преподавателя, причина пересмотра (при редактировании). Если оценка ещё не выставлена — показывается нейтральный статус «Ожидает проверки» (без ложного «Не зачтено»).
4. **Отдельная оценка ИИ (Автоматическая проверка)** — балл и замечания/разбор от ИИ, если они были сохранены. Оценка ИИ не подменяет экспертную оценку преподавателя и не затирается при сохранении экспертной оценки. Если ИИ ещё не проверял работу — явно пишется «Оценка ИИ отсутствует».

Для не-ДДС работ (где эталон действительно есть — оператор 112, сопоставление полей карточки) сохранён классический split-screen (эталон слева, ввод справа).

## 2. Архитектура и изменения в компонентах

### Backend
1. **`backend/core/ticket_generator.py`**:
   - Удалена автоматическая генерация фиктивного `dds_etalon` с дефолтными 30 секундами и синтетическими этапами при создании билета (`dds_etalon=None`).
2. **`backend/schemas/domain_02.py`**:
   - `DDSEtalon.confirmation_time_limit_seconds`: значение по умолчанию изменено на `None`.
   - Добавлен строгий валидатор `mode="before"`, отсекающий булевы значения (`True` не превращается в `1`), числа `<= 0` и дробные числа.
3. **`backend/api/router_tickets.py`**:
   - Устранена порча карточки: `content["incoming_card"]` больше не пересоздаётся вслепую при обновлении несвязанных полей билета. Пересборка происходит только при реальном изменении фактов (`plot`, `category`, `subcategory`, `ground_truth`, `etalon_services`) либо при первичном создании.
   - Поддержано явное удаление эталона ДДС: передача `ticket_in.dds_etalon = None` очищает ключи `dds_etalon` из `ground_truth` и `settings`.
4. **`backend/api/router_analytics.py`**:
   - Строгая изоляция карточки и сессии: действия и входящая карточка берутся только из попытки с совпадающим `card_id`. Исключены утечки между попытками курсанта.
   - Проверка авторства: действиями курсанта признаются только записи с `actor_id == cadet_id`. Системные статусы («Добавлена», «Получена службой») и анонимные системные комментарии отфильтрованы.
   - Входящая карточка больше не подставляется в `student_answer` для ДДС.
   - Назначенная служба вычисляется строго из роли/задания курсанта, а не из первого элемента списка служб.
   - Норматив своевременности: если время направления или доставки карточки в службу не зафиксировано, фиктивный отсчёт от 0 не генерируется (`is_recorded=False`, «Время направления карточки не зафиксировано»).

### Frontend
1. **`frontend_react/app/teacher/tickets/page.tsx`**:
   - Удалены форма и блок отображения «Эталон действий ДДС» в базе билетов.
   - Удалены стейты `editDds...` и передача `dds_etalon` при сохранении/редактировании билета.
2. **`frontend_react/components/teacher/split-screen.tsx`**:
   - Удалена колонка «Эталон» и 4 блока сравнения («1. Решение», «2. Своевременность», «3. Ход и результат», «4. Содержание комментария») для ДДС.
   - Реализованы 4 понятных блока для ДДС:
     - Блок 1: `1. Исходная карточка происшествия (контекст задания)` (`data-testid="incident-context-card"`).
     - Блок 2: `2. Действия курсанта` (`data-testid="student-column"`).
     - Блок 3: `3. Экспертный разбор и замечания` (`data-testid="teacher-grade-block"`).
     - Блок 4: `4. Автоматическая проверка ИИ` (`data-testid="ai-grade-block"`).
   - Для не-ДДС сохранён двухколоночный режим (`split-screen-columns`, `etalon-column`, `student-column`).
   - Устранено ложное отображение «Не зачтено» для завершённых работ без оценки (показывается нейтральный бейдж «Ожидает проверки» и текст «Оценка не выставлена»).
   - Устранён рендер `[object Object]` для структурированных ошибок `error_details`.
3. **`frontend_react/components/teacher/grade-dialog.tsx`**:
   - Удалена колонка «Эталон действий» и плашки о его отсутствии.
   - Отображаются краткий контекст инцидента и фактические действия курсанта.
   - Добавлена кнопка «Перейти к полному разбору работы →» (`onOpenSplitScreen`).
   - Раздельно выводятся оценка ИИ («Оценка ИИ отсутствует» или процент) и экспертная оценка преподавателя.

## 3. Отменённые проверки тестового файла ревьюера Кодекса

В соответствии с прямым указанием ТЗ файл чужого ревьюера (`frontend_react/tests/27_teacher/dds-grading-context-review.test.tsx`) **не переписывался и не подгонялся**.
Кодекс актуализирует свои тесты отдельным проходом. Ниже зафиксированы проверки Кодекса, которые перестали быть актуальными в связи с отменой эталона ДДС:

1. **`it('does not leave raw legacy keys and CSS values in the DDS etalon')`** (строка 41):
   - Проверка: `screen.getByTestId('etalon-column').textContent`
   - Причина неактуальности: для ДДС работ колонка `etalon-column` отменена пользователем. Карточка происшествия вынесена в отдельный блок «Исходная карточка происшествия» (`incident-context-card`).
2. **`it('does not replace an unspecified historical time requirement with thirty seconds')`** (строка 72):
   - Проверка: `within(screen.getByTestId('etalon-column')).queryByText(/^30 сек\.$/)`
   - Причина неактуальности: в разборе ДДС больше нет колонки эталона и критерия своевременности эталона с дефолтным требованием норматива 30 секунд.

При этом остальные 4 теста из файла Кодекса **успешно проходят**:
- `does not claim an ungraded completed work has failed` — PASS
- `does not present incoming legacy card fields as cadet authored answer` — PASS
- `renders structured historical errors without object Object or losing the explanation` — PASS
- `shows the separately saved AI and teacher scores in the full grading view` — PASS

## 4. Устранённые реальные дефекты

1. **Затирание фактов исходной карточки при редактировании билета**:
   В `backend/api/router_tickets.py` при любом PATCH билета вызывалась генерация `content["incoming_card"]` из сырых ключей, из-за чего затирались существующие поля (например, `injured: "да"` сбрасывалось на `"нет"`). Поведение исправлено: карточка пересоздаётся только если изменились ключевые факты вызова.
2. **Превращение `True` в `1` в Pydantic**:
   В `DDSEtalon` поле `confirmation_time_limit_seconds` при передаче `True` приводилось к `1`. Добавлен строгий валидатор.
3. **Подмена действий курсанта входящей карточкой**:
   `student_answer` для ДДС больше не возвращает входящую карточку из `filled_data`. Действиями считаются только реальные шаги с `actor_id == cadet_id`.
4. **Технический мусор и `[object Object]`**:
   В `split-screen.tsx` структурированные ошибки парсятся через извлечение `message || error || text` вместо неявного строкового приведения. Исключены ключи `fio`, `phones`, `aon`, `visClass`, `bricks`, `speaker`, `gender`.
5. **Ложный статус «Не зачтено»**:
   Завершённая работа, ожидающая проверки преподавателя, отображает нейтральный бейдж «Ожидает проверки» и «Оценка не выставлена».
