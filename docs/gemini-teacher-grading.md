## Что требуется пользователю

Преподаватель должен открыть завершённый урок, выбрать курсанта и выполненный билет, нажать «Выставить оценку», ввести балл и комментарий и сохранить. Сейчас прямого действия в истории нет; существующая форма спрятана в сплит-скрине, требует ручного поиска сессии и меняет зачёт на 100/0.

ТЗ системы требует экспертной оценки, обратной связи преподавателя и аудита изменений. Шкала в исходном ТЗ не задана: используем существующую шкалу проекта **0–100**, включая 0 и дробные значения. Оценка ИИ и экспертная оценка должны отображаться раздельно, итоговая оценка учитывает последнюю экспертную при её наличии.

Это задача реализации. Не ограничивайся описанием найденных проблем.

## Воркер frontend: понятный путь из истории

Основные файлы: `app/teacher/analytics/page.tsx`, компоненты преподавателя и соответствующие типы. Прочитай локальную документацию Next из AGENTS.md.

1. Путь: «Журнал оценок» → «История уроков» → «Подробнее» у урока → курсант / «Билеты» → конкретная работа. Для завершённой работы без оценки показывай кнопку **«Выставить оценку»**, для работы с итоговой оценкой — **«Изменить оценку»**. Начинать нужно именно из истории; ручной ввод ID сессии для этого не требуется.
2. Обе кнопки открывают доступный диалог с названием, содержащим слово «оценка». В нём видны имя курсанта и название билета, строки **«Оценка ИИ»** и **«Экспертная оценка»**, контекст ответа и эталона либо доступ к разбору этой же работы. При отсутствии оценки выводи понятное «Не выставлена» / «Нет оценки ИИ».
3. Поля формы:
   - числовое поле с доступным именем **«Балл»**, диапазон 0–100, дробные значения разрешены;
   - многострочное поле **«Комментарий преподавателя»** для обратной связи;
   - при изменении существующей итоговой оценки — обязательное поле **«Причина изменения»**, строка из пробелов не считается причиной.
4. При первой оценке без предыдущего результата комментарий можно оставить пустым; непустую причину для API заполни понятным служебным текстом «Первичная экспертная оценка». При изменении отправляй введённую преподавателем причину.
5. Кнопки **«Сохранить»** и **«Отмена»**. Отмена ничего не записывает. Пустой балл не превращается в 0. Во время запроса повторное сохранение заблокировано. Ошибка сервера выводится в `role="alert"` внутри формы, значения сохраняются, форма остаётся открытой. Успешное сохранение закрывает форму.
6. Отправляй числовой балл непосредственно в API экспертной оценки, без промежуточной апелляции и без преобразования «зачтено» в 100 или «не зачтено» в 0. Используй авторизацию из текущей сессии.
7. После сохранения обнови данные истории, выбранного ответа и загруженных агрегатов. После перезагрузки страницы оценка и комментарий должны приходить с сервера. Нельзя считать локальное изменение React-state доказательством сохранения.
8. Для активного несданного ответа не предлагай выставление оценки. Завершение урока без отправленной работы само по себе не означает, что ответ можно оценить.
9. Сохрани светлую/тёмную темы, доступные подписи полей и нормальную компоновку на узком экране. Исправь старую кнопку «Изменить оценку» в разборе так, чтобы она использовала тот же числовой механизм. Старые API апелляций не ломать ради нового UI.

## Воркер backend: первая оценка, изменение и целостность

Основные области: `backend/api/router_analytics.py`, `backend/core/gradebook_records.py`, схемы analytics/lessons/dds, построение истории уроков.

### Контракт

Используй существующий **POST `/api/v1/analytics/records/{record_id}/grade-override`**:

```json
{"score": 73.5, "reason": "Учтён обоснованный ответ", "comment": "Проверьте порядок вызова служб"}
```

- Поддержи первую оценку отправленной карточки без `TicketResult` и без оценки ИИ. В этом случае `record_id` — существующий `IncidentCard.card_id`, создавать фальшивый result/session/card ID нельзя.
- Сохрани поддержку существующих идентификаторов `TicketResult` и `EvaluationResult`, однозначно разрешая конкретную попытку.
- Ответ сохраняет текущий контракт: `record_id`, `session_id`, `old_score`, `new_score`, `teacher_id`, `updated_at`, `reason`. Для первой оценки `old_score = null`, настоящий прежний 0 остаётся 0.
- GET `/api/v1/analytics/records/{record_id}` возвращает текущие `score`, `teacher_comment`, `expert_modified_by`, `expert_modified_at` и дополнительные nullable-поля **`automatic_score`**, **`expert_score`**. `score` — итоговый балл. Исходный балл ИИ сохраняется после нескольких экспертных изменений.
- GET `/api/v1/lessons` возвращает у каждой доступной для оценки попытки в `students[].tickets[]` реальные **`record_id`** и **`session_id`**, а также актуальный `score`. Для карточки без `TicketResult` канонический `record_id` остаётся её `card_id` после первой оценки. Не путай ID сценария, назначения группе, личной сессии и результата.
- История, разбор, сводные показатели и повторная загрузка должны согласованно читать сохранённый итоговый балл. Первая оценённая попытка учитывается в `graded_attempts` и среднем балле ровно один раз.

### Обязательные ограничения

- Преподаватель может оценивать только свои работы. Другой преподаватель и курсант получают 403 без изменения данных и без записи об успешном изменении оценки.
- Для неизвестного результата — 404. Для активной несданной попытки — 409. Для некорректного балла и пустой после `strip()` причины — 422.
- Проверяй завершённость/отправку на сервере, а не только скрывай кнопку. Не выставляй автоматический «зачёт» по выдуманному порогу: результат должен учитывать действующие критерии проекта.
- Каждое сохранение, в том числе первой оценки, записывает `UserActionLog` с существующим действием `GRADE_OVERRIDE` (или совместимым `GRADE_MODIFIED`): автор, timestamp, идентификатор работы, прежний балл, новый балл, причина и комментарий.
- Оценка и аудит сохраняются одной транзакцией. Ошибка записи аудита откатывает изменение оценки.
- Изменение одной карточки не должно оценивать другой билет или другую попытку в той же сессии. Не используй сессионный fallback при неоднозначном наборе карточек.
- Исходная оценка ИИ, её ошибки и метрики не уничтожаются экспертной правкой. Способ хранения можно выбрать; если нужна миграция — добавь её. Для старых записей без восстановимой исходной оценки ИИ возвращай null, не выдумывай балл.
