## Воркер 1 — live-мониторинг преподавателя

Файл `frontend_react/app/teacher/sessions/live/page.tsx` и связанные компоненты.

- Исправить карточки учащихся: на узкой ширине одна колонка; больше колонок только когда каждая карточка помещает имя, статус и показатели. ФИО не должно сжиматься до одной части слова на строку.
- Длинные имена, названия билетов и бейджи остаются внутри карточки. В зависимости от ширины переносить статус под имя; не скрывать важные значения.
- Исправить верхний блок запуска: на узкой ширине текст и кнопка идут вертикально, кнопка занимает допустимую ширину, не выходит за границы карточки.
- Счётчики прогресса перестраивать в 2×2 или один столбец. Подписи и цифры не обрезать.
- Поиск и переключатель «Сетка / Таблица» должны переноситься. Поиск не должен превращаться в непонятную кнопку с одной иконкой без доступного раскрытия.
- В заголовках использовать понятные названия: «Все уровни» вместо adaptive; UUID не должен занимать основной заголовок. Точный ID при необходимости — в дополнительной информации с переносом.
- Время отображать в принятом в приложении формате 24 часа, без AM/PM. Не менять смысл таймера и серверных статусов.
- Проверить цвета и контраст обеих тем; локальные `bg-white`/фиксированные серые заменить семантическими токенами или согласованными dark-вариантами.

## Приёмка координатором

Проверить в браузере реальные страницы с данными на ширинах 320, 375, 430, 640, 768, 1024, 1440 px и при увеличении масштаба до 125–150%. Сохранить скриншоты до/после для каждого проблемного экрана в двух темах; добавить их к результату.

Особые случаи: длинные ФИО/названия/статусы, пустой список, много учащихся, загрузка, ошибка API, завершённое занятие без оценки.

Не считать исправлением глобальный `overflow-x: hidden`, скрывающий элементы, уменьшение всего текста до мелкого размера или удаление подписей. Локальный горизонтальный скролл допустим для таблицы, если он обозначен и не ломает страницу. Кнопки доступны с клавиатуры, фокус виден в обеих темах. Никаких новых наложенных плавающих переключателей поверх основных действий.

Проверить тему: явная светлая при тёмной ОС; явная тёмная при светлой ОС; режим системы; перезагрузка и переходы между страницами. Обнаруженные жёстко заданные светлые поверхности исправлять локально, сохраняя единую архитектуру темы Codex.

Запустить проверку типов и профильные тесты; дополнить регрессии для поведения, которое действительно меняется. Сборка не заменяет визуальную проверку. После интеграции пересобрать frontend локального проекта с сохранением данных.
