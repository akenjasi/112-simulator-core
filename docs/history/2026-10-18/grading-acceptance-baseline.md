# Независимая приёмка оценивания преподавателем

Проверки созданы Codex до реализации Gemini на базе main `837f684`. Они проверяют согласованный контракт из [задания](../README.md); не являются утверждением, что функциональность уже работает.

Файлы принадлежат приёмке Codex, Gemini их не меняет:

- `tests/test_teacher_grading_acceptance.py` — реальные HTTP-запросы к приложению, изолированная SQLite, проверка сохранённых данных и аудита;
- `frontend_react/tests/27_teacher/teacher-grading.acceptance.test.tsx` — реальный AnalyticsPage с подставленным HTTP-сервером данных, работа через доступные пользователю кнопки и поля. AI-отчёт группы исключён как отдельная функция.

## Запуск

Из корня репозитория:

```bash
npm --prefix frontend_react test -- tests/27_teacher/teacher-grading.acceptance.test.tsx
npm --prefix frontend_react run typecheck

docker run --rm \
  -v /home/cidralitr/uni/hakaton-arseni/112-simulator-core:/app \
  -w /app -e DATABASE_URL= -e TESTING=true \
  112-simulator-core-backend \
  python -m pytest -q --tb=short tests/test_teacher_grading_acceptance.py
```

Пустой DATABASE_URL перед импортом приложения заставляет `tests/conftest.py` создать приватную временную SQLite-базу. Рабочая база не используется. HTTP-аутентификация проверяется с тестовыми пользователями и тестовым ключом.

## Исходное состояние, 18.10.2026

- API: **10 прошли, 7 упали**, всего 17.
- UI: **1 прошёл, 8 упали**, всего 9.
- TypeScript: успешно после проверки типов самого нового тестового набора.

Подтверждённые пробелы API: первая оценка по card_id получает 404; нет отдельных automatic_score/expert_score в ответе; причина из пробелов принимается; активная несданная попытка может получить экспертный балл.

UI: история урока и раскрытие билетов работают на фикстуре; восемь проверок останавливаются на отсутствии прямого действия оценки. Проверка отсутствия действия у активной несданной работы проходит. После появления кнопки эти же тесты дойдут до числового сохранения, отмены, ошибок API, блокировки повторного запроса и восстановления после повторного открытия страницы. Успех этих следующих шагов пока не подтверждён.

Проходящие API-проверки подтверждают границы балла, базовую проверку пустой причины, запрет чужой правки и правки курсантом, 404 неизвестного результата, изоляцию второй карточки в проверенном сценарии и откат при сбое аудита. При первой оценке дополнительные проверки истории и сводки пока заблокированы ранним 404; после исправления они проверятся тем же тестом.

## После реализации

Codex сверяет diff, повторяет эти тесты самостоятельно и проверяет весь пользовательский путь в браузере. Дополнительно запускаются существующие регрессии оценок, прав и журнала, typecheck и static production build. Набор принимается после исправления реализации; тесты не переписываются под получившийся результат. Если контракт меняется по согласованию с пользователем, изменение тестов отдельно проверяет Codex.
