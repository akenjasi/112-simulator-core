# Локальный inference отчётов

Отчёты используют один локальный OpenAI-compatible llama.cpp `/v1/chat/completions`, с ограниченным SSE-потоком. Контракты API, очередь и права описаны в [отчётах ДДС](../product/reports.md).

## CPU и GPU

По умолчанию `make llm-up` и `make up WITH_LLM=1` используют `docker/compose/llm-cpu.yml`: закреплённый CPU image, ноль GPU-слоёв, четыре потока, контекст 8192 и один слот. Выбор GPU — явный `LLM_RUNTIME=gpu`; прежний CUDA image и NVIDIA CDI остаются в `llm.yml`.

Создайте приватную конфигурацию из `.env.llm.example`, задав существующий абсолютный DDS_LLM_MODEL_PATH. Модель монтируется read-only с create_host_path=false. Не добавляйте реальные env-файлы в Git.

```bash
make llm-up LLM_ENV_FILE=/absolute/private/.env.llm
make up WITH_LLM=1 LLM_ENV_FILE=/absolute/private/.env.llm
# Для GPU к той же команде добавить LLM_RUNTIME=gpu.
```

Для logs/down передавайте тот же WITH_LLM, LLM_RUNTIME и LLM_ENV_FILE. Runtime не скачивает модель. Images и веса необходимо подготовить до автономной работы.

На хосте DDS_LLM_BASE_URL — `http://127.0.0.1:8081/v1`, в общей Compose-сети — `http://llm:8080/v1`, модель — `dds-qwen`. Для локального Python backend параметры передаются в environment; env-файл Compose не экспортируется в shell. Health — `/health`, не `/v1/health`.

## Нагрузка и освобождение памяти

Один backend-процесс и co-located runtime обязательны. CPU/RAM проверяются до запуска модели. Настройки передаются backend, включая offline Compose:

| Параметр | По умолчанию | Значение |
|---|---|---|
| DDS_REPORT_CPU_MAX_PERCENT | 40 | CPU должен быть ниже порога |
| DDS_REPORT_IDLE_SECONDS | 30 | Непрерывное окно простоя перед генерацией |
| DDS_REPORT_RAM_RESERVE_MB | 2048 | Резерв памяти сверх модели, MiB |
| DDS_REPORT_MODEL_BUDGET_MB | 8192 | Бюджет холодной загрузки имеющейся 9B, MiB |
| DDS_REPORT_CANCEL_TIMEOUT_SECONDS | 30 | Ожидание подтверждённой остановки перед учебной работой |

Память под спящую модель резервируется до её пробуждения; для загруженной достаточно установленного свободного резерва. При падении доступной RAM ниже 1 ГиБ выполняющийся отчёт прерывается. Значения консервативны: если свободной памяти недостаточно, очередь ждёт без срока готовности. Точный бюджет уточняется измерением на целевом оборудовании.

Во всех поставляемых вариантах включены `--sleep-idle-seconds 10` и `/slots`. Сон выгружает модель и KV cache; следующая генерация повторно загружает веса. `/props` и `/health` не будят модель. Backend не получает Docker socket. Небольшие batch/ubatch=32 и SSE ping/progress позволяют runtime замечать отмену во время обработки промпта. Отмена не означает мгновенное освобождение RAM: после остановки действует десятисекундный idle timeout.

Самостоятельный offline-комплект использует тот же закреплённый CPU image и параметры сна, ASR/TTS выключены. Его перенос описан в [offline](offline.md). Рабочий сервис не перенастраивается одной установкой нового backend: Compose необходимо применить отдельно в согласованное окно.

## Проверка настоящего runtime

Сначала проверяйте отдельный тестовый экземпляр с теми же весами, без рабочей БД. Сборка должна поддерживать `--sleep-idle-seconds 10 --slots`; тестовый экземпляр не должен обслуживать занятия. Веса монтируются read-only. Для CPU используйте batch/ubatch=32 и ограниченное число потоков.

```bash
python -m backend.scripts.check_report_runtime \
  --base-url http://127.0.0.1:18081/v1 \
  --container your-isolated-llama-container
```

Команда создаёт только синтетический запрос: подтверждает занятие слота, отменяет поток, проверяет прекращение вычислений, сон, снижение RSS (если передан container) и повторную успешную генерацию. БД не открывает. Вывод — JSON с результатами и объёмом памяти; текст запроса не содержит персональных данных. На медленном CPU проверка занимает несколько минут. Контекст тестового экземпляра и полный контекст поставки требуют отдельных измерений памяти.

Операторские classifier/ASR/TTS и генератор реплик остаются отдельными потребителями. Персональные данные и сырой текст докладов не нужны для приёмки отчётов. Нагрузочная и методическая приёмка не заменяются одним успешным запросом модели.

Проверка 19.10.2026: отдельный CPU runtime b11723-31288c9c6 (закреплённый image из llm-cpu.yml), Qwen3.5-9B-Q4_K_M, два потока и контекст 2048 подтвердили отмену слота, сон и повторную генерацию. RSS во время проверяемого запроса — 5 474 365 440 байт, после сна — 80 109 568 байт; повторный синтетический отчёт — 799 символов. Это подтверждение жизненного цикла, не измерение максимальной памяти при контексте 8192 и не методическая оценка текста. Рабочий runtime и БД проверкой не изменялись.
