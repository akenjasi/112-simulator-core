# Локальный inference коротких сводок

Сводки используют Qwen3.5-4B-Q4_K_M через llama.cpp `/v1/chat/completions`, только CPU. Штатно: четыре потока, один слот, контекст 8192, ноль GPU-слоёв. Контракт и права — в [отчётах](../product/reports.md).

## Подготовка и запуск

Вес `models/llm/Qwen3.5-4B-Q4_K_M.gguf`: 2 740 937 888 байт, SHA-256 `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`. Источник — [Unsloth](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF), ревизия e87f176479d0855a907a41277aca2f8ee7a09523. `make models WITH_LLM=1`, `make up`, `make llm-up` и offline-упаковщик подготавливают отсутствующие стандартные веса с проверкой хеша; приложение веса не скачивает.

Приватный `.env.llm` создаётся из `.env.llm.example`. Его наличие включает модель в обычные make up/up-prod/down/logs; внешний путь задаётся LLM_ENV_FILE, WITH_LLM=0 отключает подключение. Пользовательский файл GGUF должен существовать. Стандартный backend на хосте обращается к http://127.0.0.1:8081/v1; Compose — к http://llm:8080/v1. Алиас DDS_LLM_MODEL должен совпадать у backend и runtime (по умолчанию dds-qwen).

CPU image закреплён digest и использует b11723. GPU image не используется: `LLM_RUNTIME=gpu` отклоняется, прежний llm.yml ссылается на llm-cpu.yml. В контейнер не передаются GPU-устройства; NVIDIA_VISIBLE_DEVICES=void и пустой CUDA_VISIBLE_DEVICES отключают их выбор. Те же ограничения заданы offline-поставке. Backend ожидает healthy runtime при Compose-запуске; проверяйте оба /health. Ошибка модели не требует удаления БД/томов.

## Постоянные системные префиксы

Два промпта с примерами находятся в backend/prompts/reports/summary-student.txt и summary-teacher.txt. Изменения требуют перезапуска backend. Данные отдельного занятия находятся только в пользовательском JSON с outcome/strengths/priority/practice; баллы выводит код отдельно.

Worker автоматически готовит оба префикса при доступных ресурсах и отсутствии учебной работы. Первый запрос также может подготовить нужный префикс, если фоновая подготовка ещё не завершилась. Форматирование берётся через /apply-template, постоянная часть до пользовательского содержимого обрабатывается через /completion с n_predict=0 и сохраняется через /slots/0?action=save. Перед генерацией восстанавливается соответствующий префикс. Для гибридной Qwen включены cache-prompt, cache-ram 512, ctx-checkpoints 16 и checkpoint-min-step 256.

Ключ состояния включает SHA-256 подготовленных весов, build_info runtime, размер контекста, отключённое рассуждение и точный отформатированный префикс. По умолчанию digest берётся из проверяемого манифеста стандартных весов; при пользовательской поставке передайте backend проверенный DDS_LLM_MODEL_SHA256. Метаданные runtime должны подтверждать Qwen3.5-4B. Смена текста/версии/контекста/весов создаёт другой ключ; повреждённое или несовместимое состояние обрабатывается заново.

Состояния хранятся только в приватном Docker volume llm_prompt_cache (/cache), вне Git и GGUF. Они содержат инструкции, учебные примеры и заголовок пользовательского сообщения; данные курсантов не сохраняются в этих файлах. Пробные состояния двух ролей занимали около 326 MiB, размер зависит от промпта и runtime. Для нового целевого стенда префиксы вычисляются его CPU после установки; перенос бинарного кэша не заменяет проверку совместимости.

DDS_LLM_SLEEP_IDLE_SECONDS=-1 сохраняет веса в RAM между запросами. Сохранённые файлы переживают перезапуск runtime. DDS_LLM_SLOT_CACHE=false отключает дисковые состояния. Кэш ускоряет обработку инструкции, генерация новых слов всё равно выполняется.

## Ресурсы и ограничения

На одну сводку — один запрос, максимум 128 выходных токенов, temperature=0.1, seed=42, enable_thinking=false. Цель — два предложения до 40 слов; проверка допускает до 60 слов и требует finish_reason=stop. Внутренний ответ — JSON overview/recommendation: overview ограничен точным проверенным итогом в схеме, recommendation — одно предложение упражнения. API отдаёт обычный текст из двух предложений. Частичный ответ и неприемлемый формат не публикуются. Новое занятие отменяет и генерацию, и подготовку префикса через общий координатор.

Стандартные env-шаблоны выбирают DDS_REPORT_MODE=demo: немедленная сохраняемая очередь без ожидания низкого CPU/окна простоя, но с контролем RAM и приоритетом занятий. Явный queued сохраняет фоновое расписание. Резерв RAM — 2048 MiB, бюджет холодной загрузки — 4608 MiB, при доступной памяти ниже 1 GiB worker прерывает вычисление. Batch/ubatch — 256/128, подтверждение отмены ограничено 30 секундами. Забытое ACTIVE-занятие блокирует очередь и не закрывается автоматически.

## Проверка настоящей модели

Проверка использует синтетические данные без рабочей БД и проверяет обе роли, успех, подтверждение, точность, исправления, незавершённость и недостаток данных:

```bash
python -m backend.scripts.check_brief_reports --base-url http://127.0.0.1:8081/v1 --output data/reports/brief-v1-cpu-validation.json
```

Запускайте её на свободном или отдельном тестовом runtime: она использует слот модели. Данные исходного CPU-эксперимента с префиксами: Ryzen 5 5500 (6 ядер/12 потоков), 16 GiB RAM, 4 потока inference, без GPU. Без префикса: 16,2/16,9 с для студента/преподавателя; однократная подготовка: 8,0/7,6 с; с восстановленным префиксом: 7,4/8,0 с; восстановление около 0,12 с. После перезапуска преподавательская сводка заняла 8,3 с. Это отдельные синтетические запросы, не гарантия очереди группы. Время нескольких персональных сводок складывается последовательно.

Прежние замеры подробного разбора по каждой записи относятся к старому формату; они не описывают скорость brief_v1. Сохранённая история этих экспериментов не доказывает качество новой сводки. Последние ответы и timings проверяются командой выше.

При внедрении brief_v1 проверка обнаружила перенос фактов из примера и пропуск состояния исправления. Поэтому фактическое предложение ограничено точным значением в JSON-схеме; свободная генерация оставлена для упражнения. Итоговый CPU-прогон шести сценариев (20.10.2026) прошёл за 6,46–11,70 с на сводку; восстановлено 443/462 токена системного префикса, выходы 38–68 токенов. Сырые входы/ответы: data/reports/brief-v1-cpu-validation.json. Проверка рабочего HTTP API завершила преподавательскую задачу за 10,3 с с учётом очереди; две персональные задачи также completed. Старые четыре готовых текста удалены явной процедурой cutover, количество строк восьми таблиц учебных данных до/после совпало.

Проверка итоговой реализации после перезапуска runtime: оба префикса восстановлены за 0,36 с, преподавательская сводка — 7,99 с (462 кэшированных токена), закрытие собственного SSE-потока и подтверждение свободного слота — 1,50 с. Результат: data/reports/brief-v1-runtime-validation.json.
