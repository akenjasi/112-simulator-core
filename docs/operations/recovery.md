# Резервирование и восстановление

Статус: инструкция по существующему backup-коду. Рабочее восстановление требует выделенной среды и проверки конкретного дампа; наличие этого документа не подтверждает RPO/RTO.

`python3 -m scripts.backup_db` читает DATABASE_URL/конфигурацию установки и создаёт снимок: SQLite — `.db` через online backup API (с учётом WAL), PostgreSQL — `.sql` через pg_dump15. Публикация файла атомарна. По умолчанию каталог `data/backups`; `BACKUP_DIR` позволяет выбрать иной приватный каталог. Эта команда создаёт файл, поэтому выполняйте её только для выбранной установки.

## Безопасный порядок

1. Определить БД и каталог установки, прекратить изменения данных на время согласованного восстановления, сохранить оригинал. Не использовать пути из старого отчёта без проверки.
2. Восстановить в новую пустую БД/файл. Снимок БД не включает модели, uploads, сертификаты и `.env`: они резервируются отдельно.
3. Проверить целостность, роли/учётные записи, число и связи записей, вход и доступ к учебной истории. Только затем переключать конфигурацию приложения.

Для PostgreSQL используйте совместимый psql, явную целевую БД и `-X -v ON_ERROR_STOP=1`. Пароль не помещайте в историю shell; роли, упомянутые дампом, должны существовать. Не импортируйте дамп поверх заполненной рабочей БД.

Для SQLite остановите использующие целевой файл процессы, скопируйте snapshot в новый путь, выполните `PRAGMA integrity_check`, проверьте права. Не оставляйте WAL/SHM от другой базы по целевому имени. После проверки задайте соответствующий DATABASE_URL.

## Изолированный PostgreSQL drill

```bash
bash scripts/test_pg_backup_restore.sh
```

Скрипт создаёт собственные контейнер/сеть, заполняет отдельную тестовую БД, делает dump, восстанавливает другую БД и сравнивает контрольные строки. BACKEND_IMAGE задаёт используемый image; наличие проверяется до выделения ресурсов, целевая PG ожидается SQL-запросом по TCP. Запуск не обращается к рабочей БД, но требует Docker и места под временные ресурсы.

Для автономного CPU bundle используйте его штатные backup/restore commands из [offline-инструкции](offline.md). Старый repo drill и bundle installer — разные процедуры. Успех синтетического теста не заменяет периодический drill реальных копий и внешнее хранение вне диска приложения.
