# Фоновые отчёты ДДС

Преподаватель получает отчёт по завершённому назначенному занятию; студент — накопительный отчёт по своим занятиям и самотренировкам за семь завершённых календарных дней. Результаты, критерии и статистику рассчитывает код; языковая модель составляет пояснения и рекомендации. Отсутствие оценки не означает успех или провал, незавершённая карточка показывается отдельно. Нейротекст не изменяет оценки.

## Когда создаются отчёты

Завершение занятия ставит преподавательский отчёт в сохраняемую очередь в той же транзакции. Пропущенные события сверяются раз в минуту. Сверка начинается с первого включения нового планировщика; массового автоматического анализа старых занятий нет. Их можно запросить вручную.

Суточная граница — 00:10 Europe/Moscow. Например, после 00:10 19 октября период студенческого отчёта — 12–18 октября включительно, по времени завершения личной сессии. До 00:10 действует предыдущий расчётный день. Одна задача на студента и расчётный период; при отсутствии новых завершённых результатов или изменений оценок новый запрос модели не создаётся. При выходе старых данных из семидневного окна без появления новых повторный анализ не нужен.

После простоя сохраняется только актуальная ожидающая студенческая сводка; устаревшие ожидающие задачи помечаются superseded. Готовая история сохраняется. Преподавательские задачи не объединяются.

## Очередь и приоритет обучения

Один backend-процесс запускает один планировщик и один запрос инференса одновременно. Источник очереди — `report_jobs`, не память процесса. Ожидающие задачи переживают перезапуск; выполнявшаяся задача возвращается в очередь с новой попыткой и прежним снимком. Атомарный захват и проверка job_id/attempt/status защищают от дублей и запоздалого ответа.

Планировщик каждые 10 секунд проверяет отсутствие ACTIVE-занятий и ACTIVE/IN_PROGRESS/INITIALIZED личных сессий, CPU менее 40% непрерывно 30 секунд и запас RAM. Учитываются host и доступные ограничения cgroup. Неизвестные метрики означают ожидание. Активное занятие блокирует генерацию даже после завершения работы отдельного студента; забытые активные занятия автоматически не закрываются.

Старт учебной работы и запуск генерации используют общий координатор. Перед выдачей карточки и запуском таймера HTTP-поток закрывается, а `/slots` подтверждает прекращение вычислений. Подтверждение ограничено DDS_REPORT_CANCEL_TIMEOUT_SECONDS (по умолчанию 30 секунд); если остановку подтвердить нельзя, старт возвращает 503 с предложением повторить, без запуска таймера. Это не мгновенная остановка CPU-инструкции: runtime завершает текущий блок обработки. Частичный текст не публикуется. Ожидание и отмена ради занятия не расходуют сетевые повторы.

Временные ошибки соединения, timeout, HTTP 429 и 5xx повторяются через 5, 30 и 120 минут; затем задача получает failed. Невалидный/незавершённый ответ, недостаток данных и постоянные ошибки требуют явного повтора. Чтение и повторное открытие готового отчёта не вызывают LLM.

## API и права

| API | Назначение |
|---|---|
| GET /api/ai-analytics/lessons/{lesson_id}/data | Сохранённые факты завершённого DDS-занятия, без LLM |
| GET /api/ai-analytics/lessons/{lesson_id}/report | Состояние/результат преподавательского отчёта; 404, если ещё не запрошен |
| POST /api/ai-analytics/lessons/{lesson_id}/report | Создать/вернуть задачу; необязательный body `{"retry": true}` |
| GET /api/ai-analytics/students/me/reports | До 30 собственных отчётов студента, новые первыми |
| POST /api/ai-analytics/students/me/reports | Запросить текущий расчётный период или повторить failed через `{"retry": true}` |

POST возвращает 202 для ожидающей/выполняющейся задачи, 200 для готовой. Failed без retry даёт 409. Студенческий POST без подходящих новых данных возвращает прежний готовый отчёт, а при отсутствии истории — 204. Повтор не создаёт новую задачу и не перезапускает готовую.

Bearer обязателен. Отчёт занятия доступен ADMIN и преподавателю только своего занятия; CADET не получает групповой отчёт. Студенческие endpoints доступны CADET и определяют владельца по авторизации. Смена состава группы не переписывает исторических участников отчёта.

Ответ содержит job_id, kind, lesson_id, status, attempt, created_at/updated_at, period_start/period_end, snapshot_at, waiting_reason, next_run_at, model_used, error_code и report_text. Snapshot не выдаётся. Текст доступен только при completed; ошибка — при failed. pending с waiting_reason различает очередь, занятия, CPU/RAM, неизвестные метрики, ожидание окна простоя и сетевой повтор. Время передаётся с UTC offset; интерфейс использует Москву.

## Снимок, инференс и совместимость

Преподавательский снимок сохраняется при постановке задачи, студенческий — перед первой генерацией. Прерывание и автоматический сетевой повтор используют тот же снимок. Явный повтор failed преподавательского отчёта сохраняет прежний контракт: собирает новый снимок; готовые тексты не переписываются. Интерфейс показывает период и актуальность данных.

В LLM передаются компактные показатели по всем подходящим результатам и не более 12 примеров подтверждённых ошибок. Сырые карточки, персональные реквизиты заявителей и свободные записи докладов исключены. Лимит входа проверяется явно; превышение не приводит к незаметному отбрасыванию участников. Вывод ограничен 1200 токенами, рассуждение отключено. SSE progress/ping позволяют обнаружить закрытие соединения ещё во время обработки промпта.

Календарный период передаётся модели в московских датах с включённым последним днём; UTC-границы снимка не используются как даты текста. Период отображает интерфейс. Фактическую часть сохранённого текста — числа, критерии, подтверждённые ошибки, участников и ограничения — составляет код из снимка; модель пишет только рекомендации. Названия пяти критериев заданы в инструкции модели; невыполненный критерий сам по себе не объявляется ошибочной попыткой. Ожидание памяти и загрузки CPU дополнительно поясняется в обоих кабинетах. История занятий студента также использует московское время.

Исходная таблица dds_report_jobs сохраняется. Её строки копируются идемпотентно с сохранением ID, текста и состояния; running преобразуется в pending. Публичный Python-import DDSReportJob совместим и указывает на общую модель. Старый класс worker оставлен для совместимости, приложение его не запускает.

Прежний `/api/ai-analytics/trigger`, включая background=false, направляет запросы в общую очередь. Без новых данных возвращается unchanged; завершённый ответ не обещается синхронно. Старые AIStudentAdvice/AIGroupAdvice остаются историей и не смешиваются с новыми отчётами ДДС. В кабинете студента они подписаны отдельно. В аналитике группы новые результаты нужно открывать в отчётах отдельных занятий.

Настройка CPU, сна модели и изолированная проверка — в [инференсе](../operations/inference.md). Несколько backend-процессов/реплик не поддерживаются; готовность HTTP health не доказывает качество рекомендаций.
