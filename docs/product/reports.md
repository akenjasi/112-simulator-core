# Короткие сводки ДДС

Сводка преподавателю описывает завершённое занятие или результаты его группы; персональная — работу одного курсанта. Код считает результаты, выбирает главное затруднение и показывает сохранённые баллы. Qwen формулирует два коротких предложения: итог и упражнение. Она не выставляет оценок, не анализирует каждую телефонограмму и не подменяет подробный протокол действий.

## Формат и данные

Новые снимки имеют `report_format=brief_v1`. Модель получает только четыре поля: `outcome`, `strengths`, `priority`, `practice`. Это подготовленные кодом факты, а не свободные доклады, ФИО, UUID, оценки или журналы. Сильная сторона выбирается только среди подтверждённых критериев без затруднений. Приоритет: незавершённость карточек; затем наибольшая доля невыполнений среди проверенных критериев; затем выполненное после исправления. При равенстве сохраняется порядок confirmation, service, stage, accuracy, completion. Непроверенные критерии не означают успех. Если проверка неполна, сводка предлагает полный цикл без вывода о провале.

Промпты `backend/prompts/reports/summary-student.txt` и `summary-teacher.txt` содержат постоянные инструкции и два примера: с затруднением и без него. Цель — до 40 слов; проверка принимает ровно два предложения, до 60 слов. Выход ограничен 128 токенами, рассуждение отключено. Первая фраза ограничена JSON-схемой до точного проверенного итога, чтобы модель не переносила факты из примеров и не путала исправление с невыполнением. Модель пишет вторую фразу — упражнение; backend проверяет и соединяет две строки в обычный текст. Обрезанный или некорректный ответ не публикуется. Это методический текст модели, а не гарантия правильности всех её формулировок.

`facts_text` — отдельная короткая строка результатов, рассчитанная кодом из того же снимка. Средний сохранённый балл выводится в исходной шкале 0–100 только по оценённым работам; ноль является оценкой, отсутствие оценки — нет. Новые снимки используют ту же функцию выбора сохранённой оценки, что и ведомость. Сводка и её факты не меняют экспертные оценки. При ошибке ИИ факты остаются доступны.

## Запуск и очередь

Стандартная конфигурация `DDS_REPORT_MODE=demo` запускает короткие сводки после завершения всего занятия; самотренировка — после завершения собственного цикла. Преподавательская задача ставится первой, затем персональные. Все задачи сохраняются в общей таблице `report_jobs`; отдельных параллельных демозапросов нет. Один backend-процесс и один запрос к модели одновременно. После commit постановка будит worker, без обязательного ожидания его десятисекундного опроса.

В немедленном режиме нет ожидания CPU ниже 40% и тридцатисекундного окна простоя. Действуют проверка RAM и приоритет обучения: ACTIVE-занятие или ACTIVE/IN_PROGRESS/INITIALIZED личная сессия блокируют генерацию. Старт новой работы отменяет HTTP-поток и проверяет освобождение `/slots` до выдачи карточки и запуска таймера. При неподтверждённой остановке в течение `DDS_REPORT_CANCEL_TIMEOUT_SECONDS` (30 с) старт возвращает 503. Отменённая задача возвращается в очередь с прежним снимком; частичный текст не публикуется. Это относится и к прогреву префиксов.

Явный `DDS_REPORT_MODE=queued` сохраняет фоновое расписание: отсутствие активных занятий, CPU ниже 40% непрерывно 30 секунд, резерв RAM. Суточные студенческие сводки охватывают семь завершённых календарных дней, граница — 00:10 Europe/Moscow. При отсутствии новых результатов/изменений оценок повторного запроса нет; устаревшие ожидающие периоды superseded. В немедленном режиме суточная сверка не запускается.

Сетевые ошибки, timeout, HTTP 429/5xx повторяются через 5, 30 и 120 минут; затем failed. Ошибка формата и неполный ответ требуют явного повтора. Pending/running переживают перезапуск, в том числе прежний статус generating. Захват задачи и сохранение результата проверяют job_id/attempt/status. Чтение готового отчёта не вызывает модель.

## API и интерфейс

Адреса и права сохранены:

| API | Назначение |
|---|---|
| GET /api/ai-analytics/lessons/{lesson_id}/data | Подробные сохранённые факты без LLM |
| GET/POST /api/ai-analytics/lessons/{lesson_id}/report | Отчёт занятия, только его преподавателю и ADMIN |
| GET/POST /api/ai-analytics/groups/{group_id}/report | Свежие завершённые результаты своей группы; новая ревизия — новая задача |
| GET/POST /api/ai-analytics/sessions/{session_id}/recommendation | Персональная сводка курсанту, его преподавателю и ADMIN |
| GET /api/ai-analytics/lessons/{lesson_id}/personal-reports | Персональные сводки участников, только преподавателю занятия и ADMIN |
| GET/POST /api/ai-analytics/students/me/reports | Собственные семидневные отчёты CADET |

POST возвращает 202 при ожидании/генерации, 200 для готового. Failed повторяется через `{"retry":true}`. Отсутствие новых данных студента — прежний результат или 204; отсутствие результатов группы — 409. Bearer обязателен. Snapshot не выдаётся. `facts_text` доступен и при ошибке генерации, `report_text` — только при completed; `report_format` указывает версию. Персональный endpoint отображает внутренние pending/running как generating для совместимости интерфейса.

История попыток сообщает `report_mode=null`, если персональный endpoint не поддерживает попытку: нет связанного занятия ДДС или тип сессии отличается от CARD_ACTIONS. Такие старые попытки сохраняются в истории, но интерфейс не запрашивает для них персональные сводки. Современная самостоятельная тренировка создаёт связанное занятие ДДС и поддерживает сводки штатно.

## Переход со старого формата

Очистка выполняется явно при остановленном старом backend: `make cutover-brief-reports ARGS="--env-file /private/settings.env"` сначала показывает количество строк; добавление `--apply` удаляет готовые отчёты старого формата из report_jobs, dds_report_jobs, ai_student_advice и ai_group_advice. Перед удалением создаётся приватная JSON-копия этих строк в data/backups (права 0600). Учебные данные и оценки не удаляются.

Ожидающие/прерванные задачи сохраняются, получают новый attempt и переходят на короткий генератор. Отметка brief_v1_cutover запрещает повторный импорт старой истории; граница сверки переносится на момент перехода, чтобы автоматически не пересоздавать старые преподавательские отчёты. Повторная очистка ничего не меняет. Старый отчёт можно заново запросить явно по сохранённым результатам.

Подготовка модели, сохранённые системные префиксы и CPU-проверка — в [инференсе](../operations/inference.md). Несколько backend-процессов/реплик не поддерживаются.
