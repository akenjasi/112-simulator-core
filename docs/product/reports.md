# Нейроотчёты ДДС

Статус: действующее описание API/data/jobs/UI. Старые А-02…А-05 были этапами реализации одного потока, а не отдельными продуктами. Подключение модели описано в [инференсе](../operations/inference.md).

## Данные и права

`GET /api/ai-analytics/lessons/{lesson_id}/data` собирает сохранённые факты завершённого занятия DDS. Bearer обязателен: ADMIN имеет предусмотренное совместимостью исключение, TEACHER — доступ только к своему занятию; остальные роли получают403. Неизвестный lesson —404, незавершённый или другая целевая роль —409.

Выборка ограничена точным lesson_id и завершёнными сессиями. Учитываются исторические участники, реальные карточки/действия, результаты и оценки; отсутствующие данные отражаются счётчиками/предупреждениями. Пустой урок не заменяется другой группой. Снимок для LLM исключает содержимое filled_data и персональные реквизиты, которые сборщик/санитайзер не разрешает передавать. Комментарии и любые тексты в снимке остаются недоверенными учебными данными.

Data endpoint не вызывает LLM и не выставляет оценку. Результат нейроотчёта тоже не является автоматическим изменением экспертного балла.

## Задание генерации

`POST /api/ai-analytics/lessons/{lesson_id}/report` создаёт job или возвращает существующее. Необязательный body: `{"retry": true}`.

| Состояние | Поведение |
|---|---|
| Job ещё нет |202, сохраняется неизменяемый snapshot и pending job |
| pending/running |202 с тем же job, новый inference не запускается |
| completed |200 с сохранённым отчётом; retry не перезапускает готовый |
| failed |409 без явного retry; retry создаёт новую попытку с новым snapshot |

`GET` того же пути читает job/result; неизвестное задание —404. Ответ содержит job_id, lesson_id, status, attempt, created_at, updated_at, nullable model_used; report_text выдаётся только при completed, безопасный error_code — при failed. Сам snapshot клиенту не отдаётся.

Worker запускается в lifespan backend, атомарно захватывает pending job. Завершение/ошибка записываются только для того же job_id/attempt/running; запоздавшая попытка не перезаписывает новую. После рестарта прежние pending/running задания получают `status=failed`, `error_code=interrupted`, а не вымышленный готовый текст.

**Поддерживается один backend-процесс.** Это persisted jobs плюс in-process worker, не распределённая очередь Celery/Redis и не гарантия работы нескольких workers/реплик.

## Интерфейс и ошибки

В истории завершённого занятия преподаватель запускает отчёт, видит ожидание, сохранённый текст или понятную ошибку и явный повтор. Пустой/непригодный протокол не выдаётся за содержательный результат. Потеря сети, отказ модели, лимит контекста и отмена обрабатываются отдельно от численных оценок.

Для работающего отчёта нужен доступный HTTP runtime с правильными URL/model. Docker health backend сам по себе не проверяет генерацию модели. Проверки sanitization, изоляции, retry/stale attempt и UI есть в [тестировании](../testing.md); реальный inference и качество текста принимаются на стенде.

Остальные legacy AI-рекомендации и CSV/XLSX/PDF экспорты используют собственные API; готовность DDS report job не подтверждает их поведение. Сомнительные legacy функции перечислены в [backlog](../backlog.md).
