# Роли и доступ

Статус: действующий контракт ролей. Код и тесты проверяются при изменении; исторические задания не расширяют полномочия.

ADMIN управляет системой и учётными записями; TEACHER — своими учебными группами и занятиями; CADET — собственными упражнениями. Совместимое значение STUDENT встречается в отдельных API, но не является самостоятельной четвёртой ролью.


Роль ADMIN обслуживает комплекс и управляет учётными записями. Она не даёт
прав преподавателя: изменение сценариев, уроков, оценок, управление учебными
вызовами и действиями ДДС отклоняются сервером с HTTP 403.

## Данные и удаление

Администратор не может удалять билеты и документы базы знаний через API.
Удаление пользователя означает деактивацию с отзывом сессий; запись и история
обучения сохраняются. Физическое удаление критичных учебных данных для ADMIN
не предоставляется, в том числе после создания резервной копии. Отдельная
процедура «копия → подтверждение → физическое удаление» пока не реализована.
Существующая административная функция создания резервной копии сохранена.

## Базовая безопасность

Парольную политику, таймаут сессии и обязательность 2FA может менять только
ADMIN, чей логин входит в SECURITY_POLICY_ADMIN_USERNAMES (через запятую).
Если переменная отсутствует, право имеет INITIAL_ADMIN_USERNAME, по умолчанию
admin. Пустое значение запрещает изменение всем. Переменная задаётся в локальном
.env установки, а не через API управления пользователями.

При создании пользователя пароль содержит не менее восьми символов; политика
MIN_PASSWORD_LENGTH может увеличить минимум. Форма показывает это ограничение,
а ошибки проверки API выводятся текстом с названием поля. Режим
DDS_REPORT_MODE=demo меняет порядок запуска ИИ-отчётов и не влияет на создание
пользователей: учётные записи сохраняются в настроенной БД.

Форма политик показывает причину отказа сервера и блокирует повторное сохранение до окончания запроса. Обязательная 2FA отклоняется, пока не настроена для всех активных пользователей; подключение 2FA для курсантов пока недоступно. В административной диагностике используются нейтральные подписи базы данных, применимые к SQLite и PostgreSQL.

Переключатель ENABLE_OPERATOR_112_FOR_LESSONS доступен всем ADMIN независимо
от этого дополнительного права. Обновление одного параметра не требует остальных.
Неизвестные ключи и некорректные значения отклоняются; весь пакет проверяется
до изменений. Изменения записываются в аудит SECURITY_POLICY_UPDATED.

## Персональные данные

ADMIN сохраняет список пользователей для управления учётными записями,
но не получает доступ к персональным ответам, оценкам, учебным сессиям,
именному рейтингу, учебным отчётам и рекомендациям ИИ. Агрегированные
аналитические показатели и технический мониторинг остаются доступны.
TEACHER получает через список пользователей только учеников своих групп
(учитываются cadet_ids и student_group_link). Секреты исключены схемой ответа.
Новые группы преподавателя получают teacher_id автоматически. Старые группы
без владельца не открывают преподавателям доступ ко всем ученикам автоматически.

### Изоляция AI-аналитики

Маршруты legacy AI-аналитики (`/api/ai-analytics/student/{id}`, `/api/ai-analytics/group/{id}`,
`/api/ai-analytics/advice/.../read`, `/api/ai-analytics/student/{id}/refine`, `/api/ai-analytics/trigger`)
изолированы по ролям и границам владения:
- ADMIN и роли без прав преподавателя/курсанта отклоняются с HTTP 403;
- CADET имеет доступ только к собственным персональным рекомендациям; групповые отчёты,
  refine и запуск анализа для других пользователей/групп запрещены (trigger для курсанта
  всегда ограничен его собственным профилем);
- TEACHER имеет доступ к группе только при `group.teacher_id == current_user.user_id`
  (группы без владельца не являются общими);
- TEACHER имеет доступ к персональным рекомендациям и анализу ученика только если ученик
  состоит хотя бы в одной принадлежащей преподавателю группе (учитываются как `cadet_ids`,
  так и `student_group_link`);
- Запуск анализа TEACHER требует явной цели (422 при её отсутствии); параметр `all_students`
  обрабатывает исключительно уникальных учеников групп преподавателя.

### Исключения совместимости

Для сохранения принятых контрактов ДДС и стендовых проверок действуют фактические исключения:
- **DDS data/report**: доступ к данным завершённого урока (`/api/ai-analytics/lessons/{lesson_id}/data`) и генерации отчёта (`/api/ai-analytics/lessons/{lesson_id}/report`) сохранён за ADMIN и преподавателем-создателем урока;
- **Демо-сессия оператора 112**: вызов `POST /api/v1/sessions/demo` с `target_role: OPERATOR_112` разрешён для ADMIN для демонстрации и стендовой проверки звонкового тренажёра (сессии курсанта `DISPATCHER_DDS` и устаревший алиас `/api/v2/sessions/demo` для ADMIN отклоняются с кодом 403).

Эти правила относятся к API приложения. Доступ владельца сервера к Docker,
БД и файлам регулируется отдельно средствами операционной системы.
