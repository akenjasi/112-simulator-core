# Индикатор состояния системы: задание Gemini

Модель: `gemini-3.8-flash-high`, Antigravity CLI (`agy`).
Текущий этап: подготовка тестов и обсуждение; реализация ещё не запускается.

## Цель и факты

Заменить постоянный зелёный индикатор «Система активна» реальной проверкой
`GET /api/health` в desktop и mobile меню администратора и преподавателя.
Этот endpoint возвращает `{ "status": "ok", "version": "v2" }` без требований
к роли. `/api/admin/healthcheck` проверяет БД, но ограничен ролью ADMIN;
использовать его для преподавателя нельзя. Здесь «активна» означает доступность
backend, а не исправность БД, телефонии, LLM и остальных подсистем.

## Предлагаемая реализация

Один общий компонент представления и общий hook проверки состояния.
Hook вызывается один раз в каждом layout, результат передаётся обоим
экземплярам индикатора. Не запускать отдельный polling в каждом индикаторе.
Существующее оформление и авторизацию сохранить.

## Критерии приёмки

- До завершения первой проверки: «Проверка системы…», серый индикатор
  (`bg-slate-400`), без зелёного статуса.
- Только HTTP 2xx с JSON-объектом и `status === "ok"`:
  «Система активна», зелёный (`bg-emerald-500`).
- HTTP error (включая 401/403), ошибка сети, некорректный JSON,
  неизвестный или отсутствующий status: «Система недоступна», красный
  (`bg-red-500`). Не оставлять прошлый зелёный при ошибке.
- Первый запрос сразу; дальнейшие проверки каждые 30 секунд.
  Таймаут каждого запроса — 5 секунд, включая чтение тела ответа.
  Использовать `cache: "no-store"` и AbortSignal.
- Во время обычной повторной проверки сохранять последнее подтверждённое
  состояние до ответа или таймаута; успешный ответ после ошибки восстанавливает
  зелёный без перезагрузки страницы.
- Не допускать параллельных запросов и обновления из устаревшего ответа.
- Открытие/закрытие mobile меню не запускает дополнительные запросы:
  оба индикатора показывают одинаковый текст и цвет.
- При unmount остановить таймеры, отменить текущий запрос, игнорировать
  его позднее завершение. Текст доступен пользователю независимо от цвета.
- Обёртка каждого индикатора имеет `role="status"`, содержит текст состояния
  и цветную точку. Корректно переживать повторный запуск effects в StrictMode.

## Ручная приёмка после реализации

Войти как ADMIN и TEACHER, проверить обычное и мобильное меню.
При работающем backend дождаться зелёного; отключить backend или заблокировать
`/api/health` в браузере, дождаться красного (не более 35 секунд);
включить обратно и дождаться зелёного. Проверить в Network отсутствие
добавочных запросов при открытии mobile меню.
