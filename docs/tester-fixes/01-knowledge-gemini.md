# FIX-01 — реальные справочные материалы преподавателей у курсантов

## Задача Gemini

Исправить раздел «Справочные материалы» в личном кабинете курсанта: он должен читать общий каталог материалов преподавателей, показывать реальные загруженные PDF/DOCX и скачивать их с авторизацией. Это исправление представления существующего общего каталога; отдельная синхронизация/копирование файлов между ролями не требуется.

## Подтверждённая диагностика

- `frontend_react/app/student/profile/page.tsx` содержит массив `REFERENCE_DOCS` из четырёх выдуманных PDF. Счётчик и список берутся только из этого массива. Кнопка «Открыть» вызывает `alert`, реальных байтов файла нет. Запроса `/api/v1/knowledge/files` нет.
- Преподавательская страница `frontend_react/app/teacher/knowledge/page.tsx` уже использует общий API: GET/POST `/api/v1/knowledge/files`, DELETE `/files/{id}`, GET `/files/{id}/download`. Она импортирует `apiFetch as fetch` из `lib/api-fetch.ts`, который добавляет Bearer только в собственный API.
- `backend/api/router_knowledge.py`: router разрешён ADMIN/TEACHER/CADET; список читает `KnowledgeFile` без фильтра по преподавателю. POST сохраняет файл в `data/uploads`, запись в `KnowledgeFile`, автора в `uploaded_by`; list отдаёт `id`, `name`, `size`, `size_bytes`, `content_type`, `uploaded_at`, `uploaded_by`, защищённый `url`. Download читает сохранённые байты, проверяет путь. Upload/delete разрешены только TEACHER, delete — владельцу.
- Независимый настоящий API-тест `tests/test_tester_knowledge_sync.py` прошёл: преподаватель upload → курсант list → download тех же байтов; курсант не может upload/delete; аноним не может download; после удаления преподавателем документ исчезает и download даёт 404.
- Ролевая и файловая серверная цепочка исправна. Подтверждённый дефект — заглушка в кабинете курсанта, не проблема БД или доставки на сервере.

## Границы и совместная работа

- Сохранить весь существующий dirty tree; не делать checkout/reset/clean, commit/push/deploy, не читать credentials, не запускать модели и сетевые сервисы.
- Основная разрешённая правка — `frontend_react/app/student/profile/page.tsx`; при необходимости маленький компонент материалов/helper и соответствующие тесты. Backend не переписывать без нового воспроизводимого дефекта.
- В этом же файле другой воркер уже убрал 112 radar/шестиугольник компетенций (FIX-10). **Сохранить это изменение, не возвращать RadarChart/imports или 112-статистику.** Работать по текущему содержимому файла.
- Интерфейс самого занятия ДДС не менять: `app/dds`, `components/dispatcher`, `components/operator` вне этой задачи.
- Не создавать новые групповые ограничения видимости: сейчас каталог общий, изменение политики доступа не требуется.
- Не загружать файлы повторно, не менять storage/схемы и не удалять реальные записи/материалы.
- `frontend_react/AGENTS.md`: перед изменением Next.js кода прочитать применимую локальную документацию `frontend_react/node_modules/next/dist/docs/`.

## Критерии приёмки

1. Вкладка курсанта загружает `/api/v1/knowledge/files` с существующей Bearer-авторизацией (через `apiFetch` либо имеющийся auth helper). Имя, число файлов, размер и формат соответствуют ответу. Нет статичных документов или фиктивных тегов/описаний.
2. Реальный загруженный преподавателем PDF/DOCX виден курсанту при открытии/повторном открытии вкладки. При возвращении на вкладку список перечитывается, чтобы upload/delete другого пользователя отразился без пересоздания кабинета.
3. «Открыть»/«Скачать» получает защищённый URL с авторизацией и открывает/скачивает **байты файла**, не `alert`, HTML-ошибку или только имя. Object URL освобождается. Повторный клик не создаёт лавину одинаковых запросов.
4. Загрузка видна; пустой каталог честно сообщает «Материалов пока нет»; HTTP/сетевая ошибка сообщает «Не удалось загрузить материалы» с повтором. Ошибка никогда не подменяется фиктивными материалами. 401/403 не обходить.
5. Курсант не получает кнопки загрузки/удаления. Удалённый документ после обновления исчезает; 404 на открытии обрабатывается понятно, остальные файлы остаются доступны.
6. Не сломаны история занятий, профиль и реальные оценки. Не восстанавливать удалённый radar.
7. Добавленные независимые тесты не удалять/не ослаблять и не маркировать xfail/skip. В существующем `frontend_react/tests/48_student/48_student.test.tsx` тест `renders learning history and reference materials tabs` сейчас проверяет фейковые имена; заменить только эту устаревшую фикстуру/ожидания на реальный API-каталог. Изменения radar-теста согласовать с текущим FIX-10, не отменять его.

## Ручная приёмка после выкладки

В двух разных авторизованных браузерных сессиях: преподаватель загружает PDF → курсант открывает «Справочные материалы» и видит имя/размер → скачивает и получает тот же файл → преподаватель удаляет → курсант переключает вкладку туда-обратно/обновляет и файл исчезает. Аналогично для DOCX. Проверить отсутствие выдуманных файлов при пустом каталоге и понятное сообщение при временно недоступном API.
