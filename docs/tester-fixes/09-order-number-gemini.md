# FIX-09 — обязательный номер наряда при подтверждении статуса

Исполнитель: отдельный Gemini worker `fix09_order_number`. Только после команды пользователя.
Средняя сложность: совместная UI/server-валидация, idempotency и старые фикстуры.

## Факты

`components/dispatcher/services-bar.tsx`: `isConfirmDisabled` и `handleConfirmAction`
проверяют комментарий для отказа/дополнения, но не `orderNumber`.
`backend/core/dds_service_policy.py:action_error` тоже не проверяет номер.
Таким образом, отсутствие номера допускается и галочкой, и прямым API-запросом.

## Контракт

- При сохранении нового `kind=status` номер обязателен: missing/null/пустая строка/
  пробелы отклоняются; непустой номер сохраняется после trim без выдуманного значения.
- На клиенте галочка недоступна и есть понятное объяснение обязательного поля.
  Защита есть также в handler; на сервере — стабильная 422 с безопасным кодом ошибки.
- Существующие правила комментария отказа/дополнения и переходов сохраняются.
  Не придумывать особые бизнес-исключения без фиксации в результате; исходный запрос
  тестировщика требует номер при подтверждении статуса, включая отказ.
- Пустой payload не меняет состояние/историю. Повтор ранее сохранённого request_id
  подтверждается до новой валидации и не ломает legacy replay с отсутствовавшим номером.
- Не переписывать уже сохранённые истории. `kind=dispatch` не получает чужих требований
  к номеру статуса; его собственные who_accepted/summary правила сохраняются.

Scope: services-bar, DDSActionPayload/schema, action_error/apply_dds_action и адресный
mapping ошибки в клиенте при необходимости. Это точечное разрешение пользователя
менять в АРМ валидацию номера; внешний вид остальных панелей не менять.

Перед реализацией добавить UI-тесты blank/whitespace/valid и API-тесты 422/no mutation,
валидного статуса, старого replay, отказа с обязательным комментарием. Новые тесты пока
не написаны. Существующие DDS acceptance/helpers после изменения требований обновлять
валидным номером, не удалением проверок. Проверить queue/teacher workflow и EXAM.

Выполнять после FIX-07: оба затрагивают мутации DDS. Не менять таймер и политику EXAM
в этой задаче. No commit/push/deploy или изменения рабочей БД.
