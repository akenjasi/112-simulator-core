# Задача 1: Ролевая модель и Авторизация (RBAC)

## Контекст
У нас уже есть базовый механизм JWT авторизации (`backend/core/security.py` и `backend/core/deps.py`), но он не применен к роутерам. Все API сейчас открыты.

## Что нужно сделать:

1. **Защита всех эндпоинтов (RBAC)**:
   - Применить `Depends(get_current_user)` и `Depends(require_role(...))` ко всем эндпоинтам в `backend/api/`.
   - `ADMIN` и `TEACHER` имеют доступ к управлению пользователями (`router_users.py`), группами (`router_groups.py`), сценариями и аналитикой.
   - `CADET` имеет доступ только к сессиям (`router_sessions.py`, `router_call.py`), причем туда же имеют доступ `ADMIN` и `TEACHER`.

2. **Доработка эндпоинтов управления пользователями (router_users.py)**:
   - Добавить эндпоинт **Soft Delete**: `DELETE /api/admin/users/{user_id}`. Вместо физического удаления нужно устанавливать `is_active = False` (чтобы не сломать внешние ключи сессий и логов).
   - Добавить эндпоинт **Редактирования**: `PATCH /api/admin/users/{user_id}`. Должна быть возможность обновить `full_name`, `role` и сбросить `password` (переданный пароль нужно хэшировать).
   - **Ограничения для TEACHER**: Внутри эндпоинтов создания, редактирования и удаления добавь проверку: если текущий пользователь имеет роль `TEACHER`, он может оперировать только аккаунтами с ролью `CADET`. Если он пытается создать/изменить `ADMIN` или `TEACHER`, возвращай `403 Forbidden`.

3. **Исправление тестов**:
   - Поскольку API теперь закрыты, все существующие тесты (например, `tests/11_test_api_users.py`) начнут падать с `401 Unauthorized`.
   - Обнови тесты: внедри фикстуру с авторизованным HTTP-клиентом (например, создавай JWT токен для тестового админа и подставляй в заголовки).
   - Убедись, что написанный тест `tests/24_test_api_rbac.py` проходит успешно (он проверяет логику 401 и 403).

## Архитектурные требования:
- Никакого стейта в воркерах.
- Все сложные проверки ролей (например, может ли Teacher менять этого юзера) лучше вынести в `core/security.py` или оставить компактно в роутере, если логика короткая.
- Время жизни токена оставляем 8 часов (Refresh токены не делаем).
- Смена пароля только через админку (самостоятельного эндпоинта смены пароля не делаем).
