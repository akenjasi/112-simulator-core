# Задача 25: Аудит безопасности и логирование

## Контекст
Нам необходимо вести независимый аудит всех значимых (мутирующих) действий в системе. Модель данных `UserActionLog` уже присутствует в `backend/models/domain_01.py`.

## Что нужно сделать:

1. **Audit Middleware**:
   - Создай `backend/core/audit_middleware.py` (наследник `BaseHTTPMiddleware` из Starlette).
   - Middleware должен перехватывать все запросы. Если HTTP метод входит в `["POST", "PUT", "PATCH", "DELETE"]`:
     - Извлечь JWT токен из заголовка `Authorization`.
     - Декодировать токен через `decode_access_token` (игнорируя ошибки, если токен невалиден).
     - Если `user_id` найден, асинхронно записать в таблицу `user_action_logs` строку (через отдельную AsyncSession).
     - В поле `action` записывать строку вида `HTTP_METHOD /path`. В поле `role` — роль юзера из токена.
   - Подключи этот Middleware в `backend/main.py`.
   - **Важно**: Middleware не должен блокировать или ломать обработку запроса, если запись в лог упала или токен отсутствует.

2. **Эндпоинт просмотра логов**:
   - Создай новый эндпоинт `GET /api/admin/audit-logs` (можешь добавить его в `router_users.py` или создать новый роутер `router_audit.py`).
   - Эндпоинт должен возвращать список объектов `UserActionLog` (сделай Pydantic схему ответа).
   - Защити эндпоинт с помощью `Depends(require_role("ADMIN"))`.
   - Эндпоинт должен поддерживать базовую пагинацию (`limit`, `offset`).

3. **Проверка**:
   - Я подготовил тест `tests/25_test_audit_middleware.py`.
   - Убедись, что он проходит (проверяется, что GET не логируется, а POST логируется, и что эндпоинт `/api/admin/audit-logs` возвращает 200 для админа).

## Архитектурные требования:
- Middleware не может использовать `Depends(get_db)`. Для записи лога внутри middleware создавай короткоживущую сессию через `AsyncSessionLocal()`.
