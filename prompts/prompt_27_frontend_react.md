# ТЗ 27: Frontend React (Рабочее место Преподавателя)

**Статус:** Готово к выполнению фронтенд-воркером
**Расположение файлов:** `frontend_react/` (или `frontend/` в зависимости от вашей структуры)

## Контекст для Фронтенд-разработчика
Бэкенд для "Рабочего места Преподавателя" (Архитектура V2, MVP) полностью готов. Вся сложная бизнес-логика реализована на сервере в виде чистых функций (Functional Core). 
Твоя задача — реализовать UI на React, опираясь на то, что бэкенд сделает всю "грязную работу". 

## Что уже реализовано на Бэкенде (и как с этим работать фронту)

### 1. Управление группами (Сценарий 1)
- **Бэкенд умеет:** Принимать `.csv` файл, валидировать его (колонки `first_name`, `last_name`, `email`) и создавать курсантов.
- **Рекомендации по UI:**
  - Сделай drag-and-drop зону для загрузки CSV. 
  - Форма создания группы должна иметь обязательный Dropdown `profile` со значениями `OPERATOR_112` и `DISPATCHER_DDS` (это строгий Enum на бэкенде).

### 2. База билетов и Псевдо-ИИ (Сценарий 2)
- **Бэкенд умеет:** По нажатию одной кнопки генерировать пачку готовых билетов (с уникальными ФИО, адресами из реестра Москвы, телефонами и рассчитанной сложностью).
- **Рекомендации по UI:**
  - На дашборде билетов нужна кнопка "Сгенерировать пакет".
  - Рядом инпут "Количество" (по умолчанию 50).
  - Билеты приходят в готовом виде с полем `complexity` (1, 2 или 3). Отображай сложность визуально (например, зеленый, желтый, красный бейджики).

### 3. Настройка и запуск занятия (Сценарий 3)
- **Бэкенд умеет:** Сохранять конфигурацию сессии (категории, сложность). Дефолтные лимиты ошибок вычисляются автоматически (Уровень 1 -> 0 ошибок, Уровень 3 -> 2 ошибки).
- **Рекомендации по UI:**
  - Форма "Создать занятие". Поля: выбор Группы (селект), Категории (мультиселект), Сложность (радио-кнопки: `level_1`, `level_2`, `level_3`, `mixed`).
  - Поля "Лимит времени" и "Допустимое количество ошибок" сделай опциональными (placeholder "Автоматически"). Если преподаватель их не заполнил, бэкенд сам подставит правильные.

### 4. Пост-аналитика и Апелляция (Сценарий 5)
- **Бэкенд умеет:** Автоматически проверять текст курсанта (с нормализацией) и отдавать JSON с перечнем ошибок. 
- **Рекомендации по UI:**
  - В Журнале разбора реализуй **Split-Screen (Разделенный экран)**.
  - Слева выводи `etalon` (что должно было быть), справа — ввод курсанта. 
  - Ошибки из `error_details` подсвечивай красным.
  - Добавь кнопку "Изменить оценку" (Апелляция). При нажатии открывай модалку с `textarea` для комментария преподавателя. Это отправит PATCH запрос на бэкенд, и статус карточки сменится на Passed.

### 5. База знаний (Сценарий 6)
- **Бэкенд умеет:** Принимать PDF/DOCX файлы через `multipart/form-data`, очищать их имена от кириллицы/спецсимволов и отдавать обратно относительный путь.
- **Рекомендации по UI:**
  - Простой файловый менеджер (список загруженных регламентов). 
  - Отправка файла через стандартный `FormData()`. 

## Главный архитектурный совет
Не пытайся парсить CSV, вычислять сложность инцидентов или писать алгоритмы нормализации текста на стороне React. Все это делает FastAPI. Твоя зона ответственности — красивые дашборды (Tailwind / MUI), удобные формы (React Hook Form) и наглядная визуализация (Split-screen для ошибок).
