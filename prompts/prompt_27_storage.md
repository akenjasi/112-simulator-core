**Расположение файлов:**
- `backend/core/file_storage.py` (Утилиты для работы с файлами)
- `backend/models/domain_03.py` (Модель `ReferenceMaterial` для БД)

## Контекст
Реализуем Сценарий 6: База знаний (Обучение). Преподаватель может загружать файлы (PDF, DOCX) с регламентами и приказами. В рамках MVP мы складируем их локально в директорию `data/uploads/`, а в базу данных записываем только относительный путь, чтобы потом отдавать файл через эндпоинт загрузки (FastAPI FileResponse).

## Задачи для воркера

1. **Реализовать утилиты в `backend/core/file_storage.py`:**
   Создать чистые функции для работы с именами файлов (без сайд-эффектов I/O записи, запись будет в роутере):
   - **`generate_safe_filename(original_name: str) -> str`**: 
     Берет оригинальное имя (например, "Мой Приказ.pdf"), транслитерирует кириллицу (можно использовать простую замену или библиотеку `transliterate`), удаляет спецсимволы и пробелы, и добавляет уникальный хеш/UUID перед расширением (чтобы избежать коллизий).
   - **`get_relative_path(safe_name: str) -> str`**:
     Возвращает путь вида `"uploads/safe_name"`.

2. **Создать/Обновить модель БД `ReferenceMaterial` (в `backend/models/domain_03.py`):**
   Убедиться, что таблица содержит поля:
   - `id` (Integer)
   - `title` (String - оригинальное или заданное пользователем имя)
   - `file_path` (String - относительный путь, который сгенерировал `get_relative_path`)
   - `uploaded_by_id` (Integer, ForeignKey на пользователя/преподавателя)

3. **Логика Роутера (для справки):**
   Сам роутер (в `backend/api/`) при получении `UploadFile` должен прочитать байты, пропустить имя через `generate_safe_filename`, склеить `os.path.join("data", get_relative_path(...))` и асинхронно записать файл на диск (используя `aiofiles`). А в БД сохранить `ReferenceMaterial`.
