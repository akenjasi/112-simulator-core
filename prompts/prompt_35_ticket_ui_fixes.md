# ТЗ 35: Доработка UI и ID Базы Билетов

**Статус:** Готово к выполнению (Fullstack)

## Задачи для Backend-воркера

1. **Добавление `sequence_number` и `display_id`:**
   - В `backend/models/domain_02.py` добавьте поле в класс `GeneratedTicket`:
     `sequence_number: Mapped[Optional[int]] = mapped_column(Integer, nullable=True)`
   - В схеме ответа `TicketResponse` (в `backend/schemas/tickets.py`) добавьте поле `display_id: Optional[str] = None`.
   - В `backend/api/router_tickets.py` при получении списка билетов (`list_tickets`), для каждого билета формируйте `display_id` на лету, если его нужно вернуть:
     ```python
     # Вспомогательная функция (вынесите на уровень модуля)
     def make_abbr(text: str) -> str:
         if not text: return "ХЗ"
         return "".join([w[0].upper() for w in text.split()[:2] if w])
     ```
     Затем при упаковке в `TicketResponse`: `display_id = f"{make_abbr(t.category)}_{make_abbr(t.subcategory)}_{t.sequence_number}"`. (Учтите, что `t.sequence_number` может быть `None`, тогда просто подставляйте `0` или `ID`).

2. **Заполнение `sequence_number` при генерации:**
   - В функции фоновой генерации `generate_tickets_background_task` (в `router_tickets.py`) при сохранении новых билетов в БД:
     - Перед сохранением выполните запрос: `max_seq = await session.execute(select(func.max(GeneratedTicket.sequence_number)))`.
     - Распакуйте `current_seq = max_seq.scalar() or 0`.
     - Для каждого сохраняемого билета делайте `current_seq += 1` и присваивайте `ticket.sequence_number = current_seq`. Это обеспечит сквозную нумерацию, которая не сбрасывается при удалении.

## Задачи для Frontend-воркера

1. **Таблица билетов (Колонки и UI):**
   - Выводите `display_id` (например, `ПИ_ЗВ_42`) в колонке **"ID"** вместо обрезка UUID (`#EF6D0E`).
   - В колонке **"Название / Категория"** выводите ТОЛЬКО название категории. Уберите серый текст с началом фразы фабулы под ним.
   - Удалите колонку **"Прослушать"** (иконка Play) из главной таблицы. Прослушать можно будет только провалившись в "Детали".
   - Добавьте локальный поиск над таблицей билетов (поиск по `display_id`, чтобы при вводе `ПИ_ЗВ_42` таблица отфильтровалась).

2. **Удаление билетов:**
   - Удаление билета (по иконке корзины) теперь должно происходить **сразу, БЕЗ модального окна подтверждения**.

3. **Кнопки и CSS-правки:**
   - Кнопку **"Сгенерировать"** в шапке страницы сделайте больше/шире (добавьте `size="large"` или кастомный класс).
   - Кнопка **"Сбросить"** в фильтрах сейчас вылезает за пределы рамки (фрейма). Поправьте CSS/отступы/флексбоксы фильтров, чтобы она помещалась.

4. **Модальное окно "Генерация билетов":**
   - Быстрый выбор количества билетов (кнопки под инпутом): измените значения на `1`, `5`, `10`, `20` (без плюсов и слова "штучно").
   - Текст расчета времени: измените оценку на **"~30 сек на 1 билет"**.
   - **Случайная категория:** Если пользователь оставляет поле "Категория" пустым (добавьте в селект вариант "Случайная категория" или разрешите сбрасывать), то фронтенд не должен жестко требовать категорию. (Если бэкенд требует категорию обязательно, просто передавайте любую рандомную из списка на клиенте перед отправкой, либо снимите `required` и сделайте выбор рандома на бэкенде).
