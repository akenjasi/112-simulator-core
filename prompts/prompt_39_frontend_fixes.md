# ТЗ 39: Исправление багов в логике UI билетов

**Статус:** Готово к выполнению (Frontend)

## 1. Замена хардкода `CATEGORY_PRESETS` на данные с API
В прошлом ТЗ просилось использовать API для загрузки категорий и подкатегорий. Вы добавили загрузку `classifierCategories` в `useEffect`, но в самом UI (в формах создания, фильтрации и редактирования) вы по-прежнему используете хардкодный массив `CATEGORY_PRESETS`.
- Полностью удалите константу `CATEGORY_PRESETS`.
- В выпадающих списках категорий (в фильтре, в модалке генерации, в модалке редактирования) используйте состояние `classifierCategories`.
- Для подкатегорий: сделайте так, чтобы при выборе категории делался запрос `GET /api/classifier/subcategories?category={cat}` и сохранялся в стейт (например, `modalSubcategories` для генерации, `filterSubcategories` для фильтров). Отрендерите именно их.

## 2. Баг с отображением строки "null"
Бэкенд иногда возвращает `null` для квартиры, этажа или домофона.
Вы написали: `selectedTicket.ground_truth?.entrance !== undefined ? String(...) : ""`
В JavaScript `null !== undefined` дает `true`, поэтому `String(null)` превращается в строку `"null"`, которая и выводится в инпут.
- Замените везде `!== undefined` на `!= null` (это покроет и `null`, и `undefined`), чтобы в инпуты подставлялась пустая строка `""` вместо `"null"`.
- Проверьте это во всех полях адреса (квартира, этаж, домофон, подъезд) в модалке редактирования билета.

## 3. Обновление эталонных служб при открытии модалки (Fix)
Сейчас метод `handleSubcategoryChange` работает и обновляет службы, но если просто **открыть** старый билет (где было только 4 службы), новые службы не подтягиваются.
- Добавьте логику: если при открытии `selectedTicket` у него мало служб или вы хотите подтянуть полный актуальный список — сделайте запрос к `/api/classifier/details?category=...` прямо в момент открытия модалки, чтобы отобразить правильный эталонный массив служб.
