# ТЗ 42: Жизненный цикл урока, дашборд преподавателя и лобби ученика

**Цель:** Реализовать экраны и API для управления статусом группового урока (`WAITING` -> `ACTIVE` -> `COMPLETED`) для преподавателя и базовую заглушку-лобби для учеников.

## 1. Бэкенд (FastAPI)
**API Эндпоинты (`router_lessons.py` или `router_sessions.py`):**
- `GET /api/v1/lessons/{id}`: Возвращает детали группового урока (статус, выбранные настройки, статистика онлайн учеников группы).
- `POST /api/v1/lessons/{id}/start`: Переводит статус из `WAITING` в `ACTIVE`. Генерирует или начинает раздавать индивидуальные сессии (`ExamSession`) онлайн-студентам.
- `POST /api/v1/lessons/{id}/stop`: Переводит статус в `COMPLETED` (если нужно прервать вручную).

**Тесты:**
- Создать `tests/api/test_lessons_flow.py` для тестирования смены состояний `WAITING` -> `ACTIVE` -> `COMPLETED`.

## 2. Фронтенд (Next.js) - Преподаватель
**Лобби / Дашборд урока (`frontend_react/app/teacher/sessions/[id]/live/page.tsx`):**
- Если урок в статусе `WAITING`: 
  - Отображать заголовок "Ожидание учеников".
  - Показывать список студентов из выбранной группы.
  - Большая кнопка "Запустить симуляцию" (переводит статус в ACTIVE).
- Если урок в статусе `ACTIVE`:
  - Дашборд реального времени (статистика в моменте).
  - Отображение текущего прогресса учеников (какой билет решают).
  - Поле для "Заметок преподавателя" к этому уроку (сохраняется в БД).
  - Кнопка "Завершить урок".
- Если урок в статусе `COMPLETED`:
  - Итоговая статистика.

## 3. Фронтенд (Next.js) - Журнал оценок (`frontend_react/app/teacher/analytics/page.tsx`)
- Добавить вкладку или раздел "История уроков" (или использовать существующий журнал).
- Возможность развернуть конкретный урок (accordion/список) и посмотреть детализацию по каждому курсанту (статистику, заметки преподавателя).

## 4. Фронтенд (Next.js) - Лобби Ученика (`frontend_react/app/student/lobby/page.tsx`)
- Создать базовую страницу-заглушку, куда попадает курсант.
- Надпись: *"Ожидание начала урока преподавателем..."* (пульсирующий индикатор).
- Для MVP (до реализации WebSockets) добавить временную кнопку "Войти в симуляцию (ТЕСТ)", которая принудительно перекидывает ученика на `operator/page.tsx` или `dds/page.tsx` в зависимости от его роли.

## 5. Тестирование (для воркера)
- **Бэкенд:** Запусти `pytest tests/api/test_lessons_flow.py` (напиши базовые проверки смены статусов).
- **Фронтенд:** Убедись, что экраны `live/page.tsx` корректно меняют интерфейс в зависимости от статуса `WAITING` / `ACTIVE`.
