# ТЗ 44: Журнал оценок (История сессий) и исправление Live-дашборда

**Цель:** Сделать полноценную историю проведенных уроков в журнале оценок и исправить поведение Live-дашборда для завершенных уроков.

## 1. Бэкенд (FastAPI)
- Добавить или обновить эндпоинт `GET /api/v1/lessons` для журнала оценок. Он должен возвращать список всех уроков (с фильтрацией по `group_id`, если передано) с сортировкой от новых к старым.
- Убедиться, что `GET /api/v1/lessons/{id}` возвращает полную информацию о пройденных билетах каждого курсанта в этом уроке (какие билеты решены, статус, ошибки), чтобы фронтенд мог это отрисовать.

## 2. Фронтенд - Журнал оценок (`frontend_react/app/teacher/analytics/page.tsx`)
- Главный экран журнала теперь по умолчанию должен отображать **Историю запущенных занятий (уроков)** всех групп (таблица или список).
- Добавить селект "Группа", чтобы можно было отфильтровать историю только по конкретной группе.
- В строке урока должна быть кнопка "Подробнее". При клике на нее открывается детализация урока: список курсантов.
- При клике на курсанта внутри урока открывается детализация пройденных им **конкретных билетов** за этот урок (название билета, оценка, ошибки).

## 3. Фронтенд - Live Дашборд (`frontend_react/app/teacher/sessions/[id]/live/page.tsx`)
- **Багфикс:** Если мы переходим на этот экран из "Журнала", и урок уже имеет статус `COMPLETED`:
  - Убрать надписи "Ожидание старта" и "Готовность группы".
  - Скрыть кнопку "Запустить".
  - Сразу отображать итоговую статистику урока и пройденные билеты.
  - По сути, этот экран должен переключаться в режим "Read-Only отчет", если урок завершен.

## 4. Тестирование
- Убедись, что завершенный урок на экране `live/page.tsx` не предлагает себя запустить повторно.
- Проверь вывод списка уроков в Журнале оценок.
