# ТЗ 48: Личный кабинет ученика и Лобби (Фронтенд)

**Цель:** Создать универсальный дашборд ученика (с графиками компетенций) и лобби с кнопкой "Демо-запуск", которая ведет прямо на рабочее место (оператора или диспетчера).

## 1. Личный кабинет ученика (`frontend_react/app/student/profile/page.tsx`)
- **Шапка (Универсальность):** ФИО, Аватар (возможность загрузить/вставить ссылку), и переключатель (Tabs или Toggle) роли: "Оператор 112" / "Диспетчер ДДС". При переключении меняется отображаемая статистика. 
- Убрать геймификацию (никаких "Уровней", только сухие профессиональные метрики).
- **Сводка:** Карточки: Средний балл (за всё время/мес/нед) и Количество пройденных уроков.
- **Матрица компетенций:** Используй компонент `RadarChart` (Роза ветров) из библиотеки `recharts`, чтобы показать успеваемость по категориям происшествий.
- **Топ частых ошибок:** Блок со списком самых частых ошибок. Можно оформить в виде списка с прогресс-барами (красными) или тепловой картой (heatmap).
- **История обучения:** Аккордеон (как у преподавателя), где можно раскрыть прошлый урок, посмотреть билеты, ошибки и оценки.

## 2. Лобби и Демо-запуск (`frontend_react/app/student/lobby/page.tsx`)
- Страница ожидания. Текст: "Ожидание старта. Преподаватель подготавливает занятие...".
- **Кнопка "Демо-запуск":** Большая акцентная кнопка для тестирования.
- При клике на неё вызывается `POST /api/v1/sessions/demo` (с выбором роли: 112 или ДДС).
- После ответа бэкенда происходит редирект:
  - Если 112 -> редирект на `/operator?session_id=...&ticket_id=...`
  - Если ДДС -> редирект на `/dds?session_id=...&ticket_id=...`
- Убедись, что если ДДС переходит на `/dds`, интерфейс уже показывает карточку для заполнения (ДДС не слушает первичный звонок, он получает готовую карточку от 112).

## 3. Коммуникация с существующим UI
- Маршруты `/operator` и `/dds` уже существуют. На этом этапе мы просто обеспечиваем "мост" от Лобби к этим экранам через параметры URL (`?session_id=...`).
