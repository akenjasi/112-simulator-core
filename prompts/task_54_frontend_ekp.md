# ТЗ 54: Frontend — ЕКП (Динамический Опросник и Классификатор Происшествий)

**Роль:** Frontend Developer (React/Next.js)
**Контекст:** Разработка Симулятора 112. Бэкенд уже содержит все 51 тип происшествий и может рассчитывать службы через `/api/v1/classifier/calculate`. Для MVP мы создаем гибридный UI: для главных происшествий (101, 103, 104) мы хардкодим формы "как на скринах", для остальных — используем универсальный фолбэк.

## Задача
Создать компонент `IncidentClassifier` в папке `frontend_react/components/operator/` и интегрировать его в правую панель Карточки происшествия (`frontend_react/app/operator/page.tsx`).

### Правила работы с файлами
- Разрешено изменять: `frontend_react/app/operator/page.tsx`, `frontend_react/components/operator/*`.
- Разрешено создавать новые компоненты в `frontend_react/components/operator/`.
- Запрещено трогать бэкенд и базу данных.
- **TDD Requirement:** Ты должен написать компонент так, чтобы успешно проходил тест `frontend_react/tests/incident-classifier.test.tsx` (запуск: `npm run test` в папке `frontend_react`).

### Требования к UI и Компоненту
Компонент `IncidentClassifier` принимает `incidentType: string` (например, "101", "103") и колбэк `onAggregatedUpdate: (aggregatedText: string) => void`.

1. **Если `incidentType === "101"` (Пожар)**
   - Реализуй каскад кнопок (progressive disclosure).
   - Шаг 1: `Где` (Кнопки: Улица, Транспорт, Дом, Здание/объект, Опасный объект).
   - При клике на `Улица` -> Шаг 2: `Признак пожара` (Открытое пламя / Дым, Запах гари).
   - При клике на `Открытое пламя` -> Шаг 3: Появляются блоки: `Улица (пламя, дым)` (Мусор, Трава, Лес...), `Место происшествия` (Тоннель...), `Угроза людям [Да/Нет]`, `Медицинская помощь [Да/Нет]`, `Требуется эвакуация [Да/Нет]`, `Проведена ли газификация [Да/Нет]`.
   - Активная кнопка подкрашивается синим (как в shadcn/ui toggle или default button).

2. **Если `incidentType === "103"` (Скорая)**
   - Показать форму: инпуты `Фамилия`, `Имя`, `Отчество`, `Дата рождения`, `Возраст`.
   - Кнопки радио: `Пол [Мужчина / Женщина]`.
   - Кнопка: `Отказ от реагирования Скорой` (работает как чекбокс/тоггл, синяя при активации).
   - Кнопки `Угроза людям [Да/Нет]`, `Медицинская помощь [Да/Нет]`.

3. **Если `incidentType === "104"` (Газ)**
   - Блок `Где ощущается запах` (Вне помещения / В помещении).
   - При клике показать `Признаки происшествия` (Нарушение в работе, Повреждение...).
   - Блок `Пострадавший` (Пострадавший не на месте / Отказ от Скорой).

4. **Если `incidentType` любой другой (Generic Fallback)**
   - Универсальная форма.
   - Вопросы: `Угроза людям [Да/Нет]`, `Есть ли пострадавшие [Да/Нет]`.
   - Текстовое поле: `Детали происшествия` (textarea).

### Агрегация данных (Критически важно!)
Независимо от того, какую форму заполняет оператор, при каждом изменении (клик на кнопку, ввод текста), компонент должен склеивать все выбранные данные в **одну единую строку** (readable text) и вызывать `onAggregatedUpdate(text)`.
*Пример для 103:* "Фамилия: Иванов. Возраст: 45. Пол: Мужчина. Отказ от реагирования Скорой: Да. Угроза людям: Нет."
Этот текст фронтенд потом отправит на бэкенд в поле `incident_description` для автоматической проверки!

Интегрируй этот компонент в `page.tsx` вместо захардкоженных "Пилюль" (Questionnaire Pills) в правой колонке.
