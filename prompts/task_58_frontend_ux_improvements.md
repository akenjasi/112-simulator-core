# ТЗ 58: Frontend — Улучшение UX, Статусы, Пустые поля и Интеграция Оценки

**Роль:** Frontend Developer (React/Next.js)
**Контекст:** Разработка Симулятора 112. Карточка выглядит отлично, но заказчик попросил внести ряд важных правок в UX и логику, чтобы сделать интерфейс более реалистичным и удобным.

Рабочие файлы: `frontend_react/app/operator/page.tsx`, `left-panel.tsx`, `bottom-bar.tsx` и связанные.

## Задача 1: Стартовое состояние (Пустая карточка и геолокация)
Сейчас в `page.tsx` захардкожены стартовые значения (имя заявителя, точный адрес). 
**Требование:** 
- Убери хардкод имени и полного адреса (должно быть пусто). 
- Но для реалистичности давай сымитируем, что по координатам звонка подхватился только приблизительный район. Заполни по умолчанию **только**: Страна ("Россия"), Субъект ("Москва"), Населенный пункт ("Москва"), Округ (например, "СВАО") и Район (например, "Южное Медведково"). Улицы и дома должны быть пустыми!

## Задача 2: Связка Округ -> Район
В `left-panel.tsx` сейчас список районов не меняется при выборе округа.
**Требование:** Сделай простой хардкодный маппинг (Record/объект) хотя бы для 4-5 основных округов (ЦАО, СВАО, ЮАО, ЗАО), чтобы при смене округа в выпадающем списке менялись доступные районы. 

## Задача 3: Статусы заявителя
В `left-panel.tsx` замени текущие варианты в выпадающем списке "выберите статус" строго на этот список:
- очевидец
- пострадавший
- родственник
- знакомый
- ребенок
- участник

## Задача 4: Уведомления (Toast) перекрывают интерфейс
Когда нажимаем на кнопку АОН (копировать номер), всплывает Toast "Номер АОН скопирован". Сейчас он находится сверху по центру (`top-14`) и на пару секунд перекрывает сам номер телефона, что жутко бесит.
**Требование:** Перемести Toast вниз экрана (например, `bottom-10 right-10` или `bottom-10` по центру), чтобы он не перекрывал верхнюю панель телефонии.

## Задача 5: Блокировка неиспользуемых кнопок
В тренажере не будут использоваться некоторые функции. 
**Требование:** Найди кнопки "Отправить служебное сообщение / SMS" и "Связанные карточки (Дубли)". Сделай их визуально заблокированными:
- Удали модалки для них.
- Добавь класс `cursor-not-allowed` и `opacity-50`.
- Добавь стандартный HTML `title` (тултип) при наведении: "Недоступно в тренажере. Функция служит для отправки SMS заявителю" (опиши, что делает кнопка).

## Задача 6: Остановка таймера и отправка на Бэкенд
1. **Остановка таймера:** Когда оператор нажимает "Сохранить" и открывается финальная модалка (где написано "Карточка готова к сохранению"), таймер (хронометраж) **должен остановиться**. Сейчас он продолжает тикать на фоне!
2. **Интеграция с бэкендом (Критично!):** В финальной модалке при клике на красную кнопку "Передать в службы", вместо простого показа Toast, сделай реальный POST-запрос на бэкенд: `POST /api/v2/sessions/{sessionId}/evaluate` (или `/api/v1/` если v2 не работает). 
В теле (`IncidentCardSubmit`) передавай:
```json
{
  "ticket_id": "...", // из URL
  "caller_name": "...", // ФИО
  "caller_status": "...",
  "address": "...", // собранная строка адреса
  "incident_description": "...", // то, что собрал IncidentClassifier (classifierAggregatedText)
  "time_taken_seconds": 123, // сколько натикало
  "assigned_services": ["101", "103"] // массив названий добавленных служб
}
```
После успешного ответа бэкенда редиректь пользователя обратно в Лобби (`/student/lobby`) или Журнал, и покажи красивый Toast с результатом (Оценка/Баллы).
