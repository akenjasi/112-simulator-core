# ТЗ 61: Fullstack — Микросервис распознавания голоса (GigaAM-v3) и интеграция

**Роль:** Fullstack Developer (Python/FastAPI + React)
**Контекст:** Разработка Симулятора 112. У нас есть локальная нейросеть для распознавания русской речи (Sber GigaAM-v3 в формате GGUF), которая лежит по пути `/home/orborus/Desktop/A_vibecoding/models/gigaam-v3-ctc-Q8_0.gguf`. 
Необходимо создать сервис для её использования и интегрировать в тест оборудования на фронтенде.

## Задача 1: Backend — ASR Микросервис (FastAPI)
1. Создай новый роутер `backend/api/router_asr.py` (не забудь подключить его в `main.py`).
2. Сделай эндпоинт `POST /api/v2/asr/transcribe`, который принимает аудиофайл (через `UploadFile`).
3. **Логика эндпоинта:**
   - Сохраняет полученный файл во временную папку.
   - Приводит аудио к формату `16000 Hz, Mono, WAV` (можешь использовать библиотеку `pydub`, `soundfile` или системный вызов `ffmpeg`).
   - Запускает модель `gigaam-v3-ctc-Q8_0.gguf`. 
   - *Подсказка по модели:* Так как это формат `gguf` для `transcribe.cpp`, самый быстрый способ для MVP — клонировать репозиторий `handy-computer/transcribe.cpp`, скомпилировать `transcribe-cli` (через cmake) и вызывать его через `subprocess.run()`, читая stdout. Либо, если найдешь готовый Python-биндинг для GigaAM GGUF, используй его.
   - Эндпоинт возвращает JSON: `{"text": "распознанный текст"}`.

## Задача 2: Frontend — Интеграция в "Проверку оборудования"
В прошлом ТЗ (ТЗ 60) ты создал блок "Проверка аудиосистемы" в лобби студента. Теперь оживи его!
1. Добавь кнопку "Начать проверку микрофона".
2. При нажатии запрашивай доступ к микрофону (`navigator.mediaDevices.getUserMedia`).
3. Используй `MediaRecorder`, чтобы записывать голос пользователя.
4. Сделай так, чтобы запись шла, пока пользователь говорит (или по кнопке "Остановить/Начать").
5. Полученный аудио-Blob отправляй POST-запросом на наш новый эндпоинт `/api/v2/asr/transcribe`.
6. **UI:** Добавь текстовое поле под индикатором микрофона. Когда бэкенд возвращает ответ, отображай распознанный текст прямо в интерфейсе (например: *"Вы сказали: Раз два три, проверка связи"*).

## Требования
- Бэкенд должен надежно обрабатывать временные файлы, чтобы не засорять диск (используй `tempfile`).
- Фронтенд должен корректно работать с MIME-типами (браузеры обычно пишут в `webm` или `mp4`, поэтому конвертация на бэкенде в WAV 16kHz обязательна!).
- Если модель `transcribe-cli` не установлена в системе, напиши bash-скрипт `backend/scripts/setup_asr.sh`, который автоматически скачивает репозиторий, делает `cmake` и собирает бинарник, чтобы мы могли развернуть это в один клик.
