# ТЗ 61 (Обновление): Real-Time Streaming для ASR

**Контекст:** Заказчик уточнил критическое требование — распознавание должно работать **в реальном времени (Real-Time)**, без ожидания, пока пользователь закончит фразу. Аудио должно передаваться потоком (чанками), и текст должен появляться мгновенно, как при живом диалоге.

## Архитектурные изменения для микросервиса:
1. **WebSockets вместо HTTP POST:**
   - Вместо обычного POST-запроса, создай WebSocket-эндпоинт (например, `ws://<host>/api/v2/asr/stream`).
   - Фронтенд должен захватывать аудио через `MediaRecorder` с параметром `timeslice` (например, 1000 мс) или через `AudioWorklet`, и отправлять бинарные чанки (Blob/PCM) по WebSocket на сервер.

2. **Обработка чанков на бэкенде:**
   - Бэкенд склеивает чанки или обрабатывает их по мере поступления.
   - **Важно:** Модель не должна загружаться в память при каждом чанке! Она должна быть загружена один раз при старте воркера/сервера (или при открытии сокета), чтобы инференс одного чанка занимал миллисекунды.
   - *Подсказка по модели:* Если консольная утилита `transcribe-cli` (из `transcribe.cpp`) поддерживает режим стриминга через `stdin`, используй `subprocess.Popen(..., stdin=subprocess.PIPE)` и пиши чанки туда. Если это сложно реализовать на C++, можешь для MVP переключиться на Python-версию модели `GigaAM-v3` через библиотеку `transformers` (она легко висит в памяти и может глотать чанки аудио, возвращая текст).

3. **Многопоточность (Concurrency):**
   - Для MVP достаточно обрабатывать одного пользователя (один активный WebSocket). 
   - Но заложи архитектуру так, чтобы стейт (или буфер аудио) хранился локально для каждого отдельного подключения (`websocket_id`), чтобы в будущем можно было запустить несколько воркеров (Celery/Redis) или асинхронно обрабатывать несколько операторов одновременно.

4. **UI на Фронтенде:**
   - Во время проверки оборудования текст должен появляться "на лету", дописываясь в строку по мере того, как человек говорит, как это реализовано в голосовом вводе на смартфонах.

Примени эти изменения к процессу интеграции ASR!
