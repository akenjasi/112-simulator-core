# ТЗ: Строгий аудит изменения оценок (Backend)
**Роль:** Backend Developer

## Контекст
ТЗ требует: «Система должна ограничивать преподавателя в изменении результатов обучения (оценок) без фиксации в журнале». 
У нас есть middleware логирования всех мутирующих запросов, но для юридической чистоты изменение оценок (апелляция) должно явно создавать специфичную запись в логах с типом `GRADE_MODIFIED`.

## Задачи:
1. В `backend/api/router_analytics.py` найти эндпоинт `appeal_analytics_record`.
2. После успешного обновления `is_passed` и `teacher_comment`, явно добавить запись в таблицу `UserActionLog` (модель в `domain_01.py`).
3. Запись должна содержать:
   - `user_id`: ID преподавателя.
   - `action_type`: Строку `"GRADE_MODIFIED"`.
   - `endpoint`: `/api/analytics/records/{id}/appeal`
   - `details`: В JSON положить старое и новое состояние (`old_is_passed`, `new_is_passed`, `comment`).
4. Написать честный интеграционный тест в `tests/test_72_audit_grades.py`, который:
   - Делает PATCH запрос от имени преподавателя.
   - Проверяет базу данных, что запись `GRADE_MODIFIED` была успешно создана.

## Ограничения
- Не сломайте существующую логику апелляций. 
- Обращение к БД должно быть транзакционным.
