# ТЗ: Интеграция с инфраструктурой Системы-112 (PBX и СПО-112)
**Роль:** Backend & Integration Developer

## Контекст
В текущей версии `backend/api/router_telephony.py` содержит заглушки (mock) для телефонии (Asterisk ARI/AMI). Реальная интеграция с аппаратными SIP-шлюзами (например, РТУ Т16Р) работает только в режиме эмуляции. 
Кроме того, отсутствует шлюз для экспорта учебных карточек инцидентов в реальную систему СПО-112 (SOAP/REST). Нам необходимо перевести симулятор в гибридный контур.

## Задачи:
1. **Интеграция с Asterisk (SIP PBX):**
   - Установить библиотеку `panoramisk` (или аналог для работы с Asterisk) и добавить в `requirements.txt`.
   - В `backend/core/telephony_adapter.py` (создать, если нет) реализовать класс-адаптер для подключения к Asterisk через ARI/AMI.
   - Изменить `backend/api/router_telephony.py`: убрать комментарии `TODO (Asterisk ARI Integration)` и заглушки. Подключить реальный вызов к `telephony_adapter`.
   - Реализовать методы инициализации звонка, перевода вызова и получения статуса (Ringing, Up, Hungup). Параметры подключения к АТС (хост, логин, пароль) брать из переменных окружения `.env`.

2. **Шлюз экспорта в СПО-112 (SOAP/REST):**
   - Установить библиотеку `zeep` (для SOAP) и добавить в `requirements.txt`.
   - Создать `backend/core/spo_gateway.py`. В нем реализовать класс для экспорта карточки `IncidentCard` во внешнюю систему. 
   - Шлюз должен уметь отправлять данные либо по REST (через `httpx`), либо по SOAP (через `zeep`), в зависимости от настроек в `.env` (например, `SPO112_PROTOCOL=SOAP`, `SPO112_ENDPOINT=http://...`).
   - Данные карточки (адрес, описание, заявитель) должны мапиться в стандартизированный XML/JSON, ожидаемый реальными системами 112.
   - Создать эндпоинт `POST /api/integration/spo112/export/{card_id}` в новом `backend/api/router_integration.py` (не забудьте подключить роутер в `main.py`).

3. **Тестирование:**
   - Написать логику мокирования (mocking) ответов от Asterisk и SOAP-сервера в тестах `tests/test_79_integration.py`.
   - Добиться успешного прохождения тестов.

## Ограничения
- Сервер не должен падать, если Asterisk временно недоступен (использовать таймауты и circuit breaker или graceful fallback).
- В `README.md` или `DOCKER.md` добавить раздел с описанием новых `.env` переменных для телефонии и СПО-112.
