# ТЗ: Интеграция с Active Directory (LDAP)
**Роль:** Backend & Integration Developer

## Контекст
Сейчас аутентификация в `router_auth.py` происходит только по локальной базе данных приложения. Нам нужен легкий LDAP-адаптер, чтобы пользователи (например, курсанты и преподаватели) могли логиниться под своими доменными учетками (MS AD или FreeIPA), если система развернута в инфраструктуре учебного центра.

## Задачи:
1. **Зависимости:**
   - Добавьте библиотеку `ldap3` в `requirements.txt`.
2. **Адаптер LDAP (`backend/core/ldap_adapter.py`):**
   - Напишите класс/функцию `authenticate_ldap(username, password)`.
   - Метод должен считывать переменные окружения: `LDAP_ENABLED`, `LDAP_SERVER` (например, `ldap://192.168.1.100`), `LDAP_DOMAIN` (например, `corp.local` - для подстановки `username@corp.local` при бинде) или `LDAP_BASE_DN`.
   - Использовать библиотеку `ldap3` для попытки привязки (bind) с введенными логином и паролем. Если bind успешен — вернуть `True`.
3. **Модификация авторизации (`backend/api/router_auth.py`):**
   - В эндпоинте `/api/auth/login` добавьте логику: если `LDAP_ENABLED=True`, сначала попытаться авторизовать пользователя через `ldap_adapter`.
   - **Авто-регистрация (JIT Provisioning):** Если LDAP-авторизация успешна, но пользователя с таким `username` нет в локальной базе данных, нужно **автоматически создать его** с ролью по умолчанию (например, `STUDENT`) и пустым (или случайным) паролем, чтобы система могла привязать к нему сессии и токены.
   - Если `LDAP_ENABLED=False` или LDAP-авторизация не удалась, система должна сделать fallback на стандартную проверку пароля из локальной БД (для демо-пользователей и админов).
4. **Тестирование:**
   - В `tests/test_82_ldap.py` напишите тесты с использованием `unittest.mock.patch` для имитации успешного/неуспешного ответа от `ldap3.Connection`.
5. **Документация:**
   - Обновите `README.md` (или добавьте `.env.example` параметры), указав новые настройки для LDAP.

## Ограничения
- Ядро приложения переписывать не нужно. JWT-токены остаются теми же. Мы меняем только функцию валидации пароля.
- Ошибки подключения к LDAP не должны ронять сервер (использовать `try/except` и fallback на локальную БД).
